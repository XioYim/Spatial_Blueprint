## 常项参考：报错横幅（ErrorToast）接入

> 原 `报错提示UI接入方法.md` 已归档（`日志归档\报错提示UI接入方法_20260912.md`）；以下是按现状订正过的常驻参考。

**组成**
- `gui/ErrorToast.java` —— 无状态渲染工具，单方法 `render()`
- `gui/ErrorToastSupport.java` —— 接口，`setErrorToast(Component)`
- `gui/ErrorToastScreen.java` —— 无宿主界面时的独立横幅（关闭后回原界面 / 游戏）
- `network/s2c/S2C_OperationResult.java` —— 服务端失败结果**自动**调 `setErrorToast`

**接入一个 Screen**
1. `implements ErrorToastSupport` + `@Nullable private Component errorToast;`，实现 `setErrorToast`
2. `render()` 开头：`renderBackground` → 若 `errorToast != null` 则 `ErrorToast.render(...)` 并 **`return`**（早返回，下层 UI 不渲染不交互）
3. `keyPressed` / `mouseClicked` 里：`errorToast != null` 时 ESC / 点击清空并 `return true`（吃掉输入）

**触发**
- 本地校验：`errorToast = Component.translatable("..."); NotifySound.clientError();`
- 服务端失败：正常发 `S2C_OperationResult`（`failure(key)` 等）即可。**发送统一用**
  `CHANNEL.send(PacketDistributor.PLAYER.with(() -> player), new S2C_OperationResult(...))`
  —— 旧文档里的 `CHANNEL.sendTo(..., NetworkDirection.PLAY_TO_CLIENT)` 已不用。

**现状口径（与旧文档不同，以这段为准）**
- **失败一律横幅，没有聊天栏 fallback**：未实现接口的界面 / 无界面时由 `ErrorToastScreen` 顶上（`S2C_OperationResult.java:114-131`）。
- 失败横幅还会把「停在 loading 的上传报告页」先退回父屏，避免卡死。
- **成功仍走聊天**（`displayClientMessage`），只有**上传成功**走横幅。

**子屏幕触发父屏幕校验**：校验失败设完 `errorToast` 后要 `Minecraft.getInstance().setScreen(this)` 切回父屏，否则父屏不在渲染栈、toast 不显示。

**哪些不用改**：`command/` 命令系统、异步放置 Handler（界面已关）、成功通知、已有 `instanceof ErrorToastSupport` 的 else 兜底。

**lang 命名**：`spatial_blueprint.gui.<screen_id>.error.<name>` / `spatial_blueprint.message.<name>`；中英各一份。

**已接入 Screen**：`CoordinateEditScreen`、`UploadBlueprintScreen`、`PointSelectionScreen`、`PlacementScreen`、`BlueprintLibraryScreen`、`CreateEngineeringProjectScreen`、`EngineeringBlueprintScreen`、`SafeCoordScreen`、`VoidDimensionalScreen`、`BlockSubstitutionsScreen`、`BulkConversionScreen`、`ErrorToastScreen`。
