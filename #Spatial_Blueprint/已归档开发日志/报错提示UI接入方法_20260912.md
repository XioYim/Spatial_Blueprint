# 报错提示 UI 接入方法

modid: `spatial_blueprint` | Minecraft Forge 1.20.1

本文档说明如何将 `ErrorToast`（游戏式错误横幅）接入 GUI 界面，替代旧的聊天栏 `displayClientMessage` / `sendSystemMessage` 方式。

---

## 一、系统组成

| 文件 | 作用 |
|------|------|
| `gui/ErrorToast.java` | 无状态渲染工具类，单方法 `render()`，画横幅 |
| `gui/ErrorToastSupport.java` | 接口，`setErrorToast(Component)` 一个方法 |
| `network/s2c/S2C_OperationResult.java` | 服务端发失败结果时，自动调用 `setErrorToast()` |

---

## 二、接入步骤（以一个 Screen 为例）

### 第 1 步：实现接口，添加字段

```java
import javax.annotation.Nullable;

public class MyScreen extends Screen implements ErrorToastSupport {

    @Nullable private Component errorToast;

    @Override
    public void setErrorToast(Component message) {
        this.errorToast = message;
    }
```

### 第 2 步：修改 `render()` — 早返回模式

toast 出现时完全隐藏下层 UI（不渲染、不可交互）：

```java
@Override
public void render(GuiGraphics graphics, int mouseX, int mouseY, float partialTick) {
    this.renderBackground(graphics);
    if (errorToast != null) {
        ErrorToast.render(graphics, this.font, this.width, this.height, errorToast);
        return;                        // 提前返回，下层 UI 全部跳过
    }
    super.render(graphics, mouseX, mouseY, partialTick);
    // ... 其余自定义绘制 ...
}
```

> **注意**：不要把 `ErrorToast.render()` 放在 `render()` 末尾——那样下层 UI 仍会渲染和响应交互。

### 第 3 步：拦截输入（ESC / 任意点击关闭）

```java
@Override
public boolean keyPressed(int keyCode, int scanCode, int modifiers) {
    if (errorToast != null) {
        if (keyCode == 256) errorToast = null;  // ESC
        return true;                             // 吃掉所有按键
    }
    return super.keyPressed(keyCode, scanCode, modifiers);
}

@Override
public boolean mouseClicked(double mouseX, double mouseY, int button) {
    if (errorToast != null) {
        errorToast = null;
        return true;                             // 吃掉点击，同时关闭 toast
    }
    return super.mouseClicked(mouseX, mouseY, button);
}
```

## 三、触发方式

### 3.1 客户端本地校验（Screen 内部直接设置）

```java
// 把原来的：
player.displayClientMessage(Component.translatable("xxx.error"), false);

// 改成：
errorToast = Component.translatable("xxx.error");
NotifySound.clientError();
```

### 3.2 服务端返回失败结果（S2C_OperationResult）

`S2C_OperationResult.handleClient()` 会自动检测当前屏幕是否实现 `ErrorToastSupport`：

- **已实现**：自动调用 `setErrorToast()`，不需要额外代码
- **未实现**：fallback 到聊天栏 `sendSystemMessage`

所以服务端这边只需要正常发 `S2C_OperationResult.failure("xxx.key")`，接收屏幕实现接口即可：

```java
// 服务端 handler 示例
BlueprintNetwork.CHANNEL.sendTo(
    S2C_OperationResult.failure("spatial_blueprint.error.xxx"),
    player.connection.connection, NetworkDirection.PLAY_TO_CLIENT);
```

## 四、特殊情况：子屏幕触发父屏幕的校验

**问题场景**：子屏幕（如 `CreateBlueprintScreen`）调用父屏幕的方法，父屏幕的校验失败，把 `errorToast` 设在父屏幕实例上——但当前活动屏幕是子屏幕，父屏幕不在渲染调用栈内，toast 永远不显示。

**修复方式**：校验失败时，在设置 `errorToast` 之后，调用 `Minecraft.getInstance().setScreen(this)` 切回父屏幕：

```java
// 父屏幕中的校验方法
private boolean prepareCapture() {
    if (pointsMissing) {
        errorToast = Component.translatable("xxx.missing_points");
        Minecraft.getInstance().setScreen(this);   // ← 切回父屏幕，toast 才能渲染
        return false;
    }
    // ...
}
```

## 五、判断哪些消息需要改

### ✅ 不需要改（保留聊天消息）

| 情形 | 原因 |
|------|------|
| `command/` 目录下的命令系统 | 无 GUI，聊天是唯一途径 |
| 异步放置 Handler（如 `BlueprintPlacementHandler`） | 放置期间界面已关，无法弹 toast |
| 内容是**成功通知**（completed、saved、created…） | toast 只用于错误，成功反馈走聊天 |
| 已有 `instanceof ErrorToastSupport` 检查，当前是 `else` 分支 | 已优先尝试 toast，这是合理 fallback |

### ❌ 需要改成 ErrorToast

| 情形 |
|------|
| `gui/` 目录下 Screen 类内部的错误分支 |
| 消息内容是**拒绝 / 错误**（format error、limit exceeded、parse failed…） |
| 该 Screen 已实现（或可以实现）`ErrorToastSupport` |

## 七、lang key 命名规范

```
spatial_blueprint.gui.<screen_id>.error.<error_name>   # GUI 本地校验错误
spatial_blueprint.message.<error_name>                  # 通用/跨屏幕错误
spatial_blueprint.gui.error_toast.tip                   # 固定：关闭提示文字（已存在）
```

每个 key 需同时在 `zh_cn.json` 和 `en_us.json` 中添加。
