> 状态：**设计定稿，未开始实现**（2026-08-26 修订）
> 关联：`最新开发日志.md`、`D:\XioYimData\下载\测试清单.txt`

---

## 一、定位

项目蓝图**本身不放置任何方块，也不保存进度**，它只是一把钥匙 + 一个查看器：

- 显示项目边界与各子工程的区域线框
- 作为子工程蓝图的领取入口
- 携带一个 `taskSetId`，指向服务端的一份「任务集」

**真正的状态全在服务端。** 物品可丢、可复制、可补发，进度不跟着物品走。
这条是整个设计的支点 —— 它让补领、云存档、跨存档三件事同时成立。

```
项目蓝图物品（NBT 只有 taskSetId）
   └── 指向服务端的一份「任务集」
        ├── 公用项目：taskSetId 固定，全服共享一份进度
        └── 私人项目：每人激活时各生成一个 taskSetId
   任务集 → 引用一份不可变的 project.dat（坐标、旋转、子工程列表）
   进度   → 服务端 SavedData，按 taskSetId 存
```

## 二、两个物品

| | 公用项目蓝图 | 私人项目蓝图 |
|---|---|---|
| 物品 id | `public_project_blueprint` | `private_project_blueprint` |
| 附魔光效 | **有**（`isFoil()` 返回 true） | 无 |
| 材质 | `textures/item/project_blueprint_1` |`textures/item/project_blueprint_2`|
| 激活者 | **仅 OP 创造模式** | 每个玩家自己 |
| 激活时机 | 上传**之前**（上传的副本带固定坐标） | 分发后，玩家各自激活 |
| 进度 | 全服共享一份 | 每人一份 |

**未激活的公用蓝图落到非 OP 手里 → 报「非法蓝图」。**
判据是「非 OP 持有未激活的公用项目蓝图」，不能简单写成「未激活即非法」——
OP 制作过程中手上拿的就是未激活的。

## 三、激活

**激活是一个动作做三件事：**

```
生成 taskSetId  +  锁定坐标与旋转  +  在坐标占用表中登记
```

公用项目由 OP 激活一次（所有副本共享同一个 id）；私人项目由每个玩家各自激活
（各生成一个 id、各占一块地）。这个统一让「复制物品不复制进度」自动成立 ——
进度按 taskSetId 存，而 id 是激活时才生的。

**激活后坐标系不可再更改，任何人包括 OP 都不能改。**

### 激活前的校验（缺任一项拒绝并说明缺什么）

1. 坐标已锁定
2. 维度已记录
3. 子工程数 ≥ 1
4. 每个子工程文件都在
5. 坐标占用表中无重叠（见 §八）

## 四、文件布局

```
config/spatial_blueprint/
  engineering/                      ← 独立完整工程蓝图（与项目无关）
  projects/
    {projectId}/
      project.dat                   ← ProjectData：坐标、尺寸、旋转、子工程列表
      {engUuid}.litematic           ← 子工程，按 UUID 绑定到本项目
```

多个子工程绑定同一个主项目，互不冲突。

> ⚠ 文件名**只用 engUuid，不带 index** —— index 存在 `EntryData` 里。
> 带 index 的话，删除条目后重新编号会让文件名和 index 对不上
> （现有 `ProjectStorage.entryDatPath()` 就是按 index 拼路径的，是个还没绊到人的陷阱）。

## 五、创建流程与界面

### 5.1 入口分流

**主手空白蓝图 + 副手拿什么** 决定这次创建的是什么：

| 副手 | 点 [创建] 之后 | 结果 | 存放位置 |
|---|---|---|---|
| 空 | 「选择创建类型」页 | 按所选类型 | 各自分类目录 |
| 项目蓝图 | **直接进「创建子工程蓝图」页** | 该项目的子工程 | `projects/{projectId}/` |

副手拿项目蓝图时不再经过选择类型页 —— 意图已经明确，再问一遍是多余的。

> 前置条件已就绪：所有蓝图物品的 `use` / `useOn` 已限制为**仅主手**
> （2026-08-26 改动），副手的项目蓝图不会抢走右键交互。

### 5.2 「选择创建类型」页的改动

`spatial_blueprint.gui.create_blueprint.title`（选择创建类型）：

| 按钮 | 改动 |
|---|---|
| 创建空间蓝图 | 不变 |
| 创建投影蓝图 | 不变 |
| 创建次元蓝图 | 不变 |
| **创建独立工程蓝图** | 文案改名（原「创建工程蓝图」），行为不变 |
| **创建项目蓝图** | **新增**，排在独立工程蓝图下面 |

「创建项目蓝图」的特殊性：

- **仅 OP 可点**（非 OP 置灰 + 说明）
- **跳过检测报告**，直接创建 —— 项目蓝图一个方块都不捕获，
  非法方块检测无从谈起。检测落在后续创建子工程时，那条路走的是既有的完整流程
- 上限按**选区体积**（`sx × sy × sz`）判定，**不是**非空气方块数

  > 这条必须单独写一个分支。现有 `addTypeButton` 拿 `getCachedBlockCount()`
  > 比对上限，对项目蓝图会得出错误结论：一个 200×200×200（800 万体积）但内部
  > 大多是空气的选区，方块数可能只有 3 万，会被误判为通过。

### 5.3 「创建子工程蓝图」页

与「选择创建类型」页同款 UI，标题改为**创建子工程蓝图**。

```
第一行   [名字输入框] [构建时长输入框] [序号输入框]
下面     底部按钮行（与原页一致）
```

**序号**：

- 从 1 开始递增，**不可与该项目已有条目重复**
- 打开页面时**自动填入下一个可用序号**（= 已有最大序号 + 1；无条目时为 1）

  > 不能用「已有条目数 + 1」：玩家可以手填任意序号，条目为 1/2/4 时
  > 数量 3 + 1 = 4 会直接撞号。

- 玩家可手改，但**改成已存在的序号必须被拒绝**
- **客户端先拉一份该项目的条目清单**（新增一对网络消息），用于自动填号与即时查重
- **点创建时服务端再判一次**，重复则拒绝并回横幅 —— 客户端那道是体验，服务端这道是底线

**底部按钮行**：与原页一致，只有一处不同 ——「蓝图列表」改成**查看项目**，
本阶段**禁用不可点**，tooltip 写「暂未实现」。

**点击创建时的校验**：

1. 序号合法且不重复
2. 子工程选区**完全落在项目选区内**（X / Y / Z **三轴都要判**，
   Y 方向超出最容易漏，因为大多数建筑是平铺的）
3. **不检查子工程体积上限** —— 项目本身已被上限框住，子工程最大也只能等于项目

以上第 2 条**服务端必须再做一遍**。只在客户端判的话，改包就能把子工程钉到项目边界
外面，领取时算出的绝对坐标会砸到毫不相干的建筑。

**创建成功后**：空白蓝图**原样不动**，只弹一条成功横幅。
不发放任何蓝图物品 —— 子工程是给玩家领取的，创建时就发一枚出来只会让 OP 手上攒一堆。
（本页是 OP 专用，不消耗空白蓝图不构成滥用面。）

### 5.4 分类 id 与上限

⚠ **新分类绝对不能叫 `project`** —— 那个 id 已经被**投影蓝图**占用了：

```java
addTypeButton("project", "...btn.projection", ...)   // "project" = 投影蓝图
BlueprintConfig.getMaxVolumeFor("project")           // 投影的体积上限
dirFor("project") -> projections/                    // 投影的存储目录
```

也不要用 `projects`（复数）—— 与 `project` 只差一个字母，散落在 `maxVolumeFor` /
`slotLimitFor` / `dirFor` / lang key 四处 switch 里，迟早看走眼。
蓝图库那个 tab 现在正是用的 `"projects"`，**一并改掉**（它目前指向空列表，改动零成本）。

| 用途 | 分类 id | 体积上限（新配置项） | 槽位 |
|---|---|---|---|
| 项目蓝图 | `projectset` | 默认 **0 = 不限**，落到硬编码上限 160 万；按**选区体积**判定 | 不占 |
| 子工程 | `subproject` | 默认 **30 万**，按**非空气方块数**判定（走正常捕获逻辑） | **不占** |

两者都需要**独立的配置项**，不能复用独立工程蓝图那一份。

> ⚠ 实现时要审一遍所有 `switch` 到 `"engineering"` 的地方：子工程用的是
> `subproject` 分类，但功能上仍是工程蓝图（同一个物品、同样的材料清单与固定坐标放置）。
> 物品类型映射、放置链路、材料校验三处都要认这个新分类。

子工程的 `relP1` / `relP2` **存旋转后的世界偏移**，`rotation` 只作记录、领取时不再套用。

### 5.5 编辑期与冻结期

**完整流程（已定稿）：**

```
建项目（未激活）→ 反复加子工程 → 全部加完 → 激活（锁坐标 + 冻结条目表）→ 分发
```

因此判定方向是：

| 项目状态 | 能否加子工程 |
|---|---|
| **未激活**（编辑期） | ✅ 可以，反复加 |
| **已激活**（冻结期） | ❌ 拒绝 + 报错横幅 |

**激活 = 定稿**，与「激活后坐标系永久锁定」是同一套语义：条目表一旦冻结，
已领取的玩家看到的清单就不会中途变化。

> 曾经把限制写成「未激活不能建子工程」，那会与 §三 激活校验第 3 条
> （子工程数 ≥ 1）形成死锁 —— 没子工程不能激活、没激活不能建子工程，
> OP 永远走不到第一步。方向必须是上表这样。

## 六、领取

- **冷却：每个玩家的每个子工程单独计时，10 分钟一次**
- **已完成的子工程仍可领取**，只在领取时弹一次提示确认

  > 理由：已完成的工程要重建，必须先把原有方块全部拆完，且要自己出材料。
  > 这个成本本身就是门槛，不属于蓝图该拦截的范畴。
  
- **子工程蓝图不占工程蓝图槽位** —— 否则一个 16 条目的项目能把玩家槽位吃光
- **绝对坐标在领取时才算**：`任务集 origin + relP1/relP2` → 写进物品的
  `engStart` / `engEnd`。因为私人项目的 origin 是玩家激活时才定的，不能预先写死在 dat 里。

## 七、完成判定

**在放置成功的那一刻直接判定并记录，不挂在动画结束。**

代码约束（已核实）：工程蓝图现在**无论哪个模式都用后即焚**

因此 `taskSetId` + `entryIndex` 必须在**物品被清空之前**从 stack 上读出来记账 ——
清空之后再想读就没有了。

记账内容：`taskSetId × entryIndex → 完成`，写服务端 SavedData。

### 完成指令

模板占位符：`{player}` `{project_id}` `{entry_index}`，其中 **`{player}` 用玩家名**。
由服务端 `CommandSourceStack` 执行（不以玩家身份）。

## 八、坐标占用表

**每个已激活的坐标系都登记到全局表，直到项目完成或被释放。**
同一位置的后来者一律**拒绝激活**（先来后到）。

| 项 | 定法 |
|---|---|
| 判定粒度 | **包围盒重叠**，不是 origin 精确匹配 —— 否则错开一格就绕过去了 |
| 键 | **带维度** —— 主世界与下界的同一坐标不算冲突 |
| 持久化 | `SavedData`，重启后仍然有效 |
| 释放 | ① 项目完成自动释放 ② **OP 站在项目范围内执行指令释放** ③ 玩家主动放弃（UI，待办） |

## 九、跨存档

项目蓝图与子工程都可跨存档使用：OP 在单人创造档做好建筑、设定好项目，
把 `projects/{projectId}/` 整个目录拖到服务器配置文件夹即可加载。

### ⚠ 子工程蓝图必须豁免 `WorldIdentity` 校验

工程蓝图现在是「外档右键直接销毁，OP 也不例外」。不豁免的话，玩家领到子工程蓝图
一右键就没了、再领再没，整个跨存档场景不成立 —— 属**阻断项**。

**先澄清「销毁」的范围（已核实代码）**：只把玩家手上那枚物品置空
（`C2S_DiscardForeignBlueprintMessage` 里的 `setItemInHand(hand, ItemStack.EMPTY)`），
**磁盘上的 `.dat` 原封不动** —— 那是另一个存档的资产，删了会把人家好端端的蓝图一起弄没。
所以损失只是一枚物品，不是数据；但玩家永远建不成，仍然必须豁免。

现有链路（两处**各自独立判断**，因此两处都要改）：

| 侧 | 位置 | 判据 |
|---|---|---|
| 客户端 | `ForceBlueprintGuard.interceptForeignWorld()` | `category ∈ {engineering, dimensional}` 且 `!belongsToCurrentWorld(worldUuid)` |
| 服务端 | `C2S_DiscardForeignBlueprintMessage.isForeign()` | 同上（服务端复核，不信任客户端判断） |

> 服务端那道复核不能省：不校验的话，伪造一个包就能把玩家手上**正常**的蓝图洗掉。

### 豁免做法：给子工程一个标记

**`BlueprintData` 新增 `parentProjectId`（String，空表示不属于任何项目）。**
非空即豁免存档归属校验，两处判据都加同一条：

```java
// 子工程的绝对坐标是从任务集 origin 算出来的，本来就不绑定存档 —— 豁免
if (data.parentProjectId != null && !data.parentProjectId.isEmpty()) return false;
```

选这个而不是「在两处的条件里各写一遍排除逻辑」，是因为**判据落在数据本身**：
以后再多几个入口要判存档归属，只要读同一个字段就行，不会漏。

配套：

- 该字段随 `SpatialBlueprintData` 一起序列化，在**创建子工程时**写入（§五 那条路径）
- **独立完整工程蓝图仍然受存档约束** —— 它绑定的是真实世界坐标，换档照样砸建筑
- 字段名**不要叫 `projectId`**：`EngineeringBlueprintItem` 里已经有个 `engProjectId`，
  存的是工程蓝图自己的 blueprintId，两者毫无关系（见 §十一「命名冲突」）

## 十、已确认的设计取舍（不是待办）

- **项目蓝图是纯查看/分发工具**，自己不放置任何方块。
- **进度与物品解耦**：复制物品不复制进度；丢失物品不丢失进度。
- **激活后坐标系永久锁定**，OP 也不能改。
- **不存在「子工程永久关闭」**：已完成的仍可领取重建，成本由拆除+材料自然构成门槛。
- **`rel` 存旋转后的世界偏移**，`rotation` 只作记录，领取时不再套用（否则会转两次）。
- **子工程不占工程蓝图槽位。**
- **工程蓝图无论哪个模式都用后即焚**（2026-08-26 统一）。
