## 一、广播系统（他人可见的线框）—— 手持预览

### 当前已有

- **C2S_PreviewUpdateMessage** → `ServerPreviewTracker` → **S2C_PreviewBroadcastMessage** → `ClientOtherPreviewCache` → `renderOtherPlayerPreviews()`
- 渲染键：`other_[UUID]`，颜色随对方蓝图类型
- 完整结构：128 块内 + 最多 3 个（`OTHER_FULL_PREVIEW_MAX_DIST=128` `:242`，`OTHER_FULL_PREVIEW_CAP=3` `:240`）
- 适用蓝图：**仅空间蓝图 / 投影蓝图**；空白蓝图选区、项目蓝图范围框不走此套
- 上报节奏（客户端 `BlueprintSelectionRenderer:1033-1071`）：锁定时 origin / 旋转变化才发；未锁定每 `previewBroadcastInterval` 秒发一次

### 四个缺口（手持预览广播层面）

| # | 问题 | 代码位置 |
|---|---|---|
| 广播范围 | 只发给半径内的玩家，默认 `previewBroadcastRadius=256`（配置 16–1024） | `ServerPreviewTracker.broadcast():105-110`；`BlueprintConfig.java:268` |
| 线框无距离剔除 | 线框循环遍历所有缓存条目，无距离过滤 | `BlueprintSelectionRenderer.java:847-872`（方法入口 `:807`） |

| 线框无总数上限 | 完整结构有 CAP=3，线框层无上限 | `BlueprintSelectionRenderer.java:847` |

> 服务端 `level.players()` 已按维度过滤。对手持预览而言，广播扩全服 = 去掉半径检查；但下面的缺陷 2（换维度）不会因此消失，要单独补。

### 已确认的缺陷（原报告遗漏，读代码可证）

| # | 缺陷 | 代码位置 | 后果 |
|---|---|---|---|
| 1 | **清除包按半径下发 → 永久残影**：`origin=null` 时广播中心取**源玩家当前位置**而非框所在位置 | `ServerPreviewTracker:101-103` | 目标收到框后走出半径 / 源玩家把框放远处后走开再收起 → 目标客户端残影直到下线（客户端缓存只在 `LoggingOut` 清，`ClientOtherPreviewCache:103`，无 TTL） |
| 2 | **换维度完全不处理**：全仓无 `PlayerChangedDimensionEvent` 调 `ServerPreviewTracker`，客户端也不按维度清 | `ServerPreviewTracker` 仅被 `SpatialBlueprintMod:150`（登出）调用 | 源玩家换维度 → 旧维度玩家残影；目标换维度 → 旧维度的框画在新维度同坐标 |
| 3 | **锁定模式丢最后一次移动**：客户端发送后立刻记 `lastBroadcastOrigin`，服务端 2 tick 冷却把后一包**直接丢弃**不补发 | 客户端 `BlueprintSelectionRenderer:1048-1051`；服务端 `ServerPreviewTracker:73` | 2 tick 内连按两次偏移，别人看到的框停在上一格（未锁定模式定期重发，可自愈） |
| 4 | **去重不比 blueprintId / category** | `ServerPreviewTracker:64-67` | 同位置换一张同尺寸蓝图不广播 → 别人颜色不变、`fullData` 仍是旧蓝图 |

> 以上都只影响「别人看到什么」，不影响服务端正确性；1、2 在多人服易复现。已纳入 SB-014 审查手册 H 区。

## 四、渲染策略：哪些每帧、哪些缓存

### 每帧渲染（即时模式，用 MultiBufferSource）

| 内容 | 原因 |
|---|---|
| 所有 Outliner 条目（选区框、预览框、非法框等） | MC 的 `MultiBufferSource` 是即时模式，无持久缓冲；坐标要减去当前帧相机位置；`ChasingAABBOutline` 每帧插值；淡出 alpha 依赖 `partialTick` |
| `specialEntries`（容器/告示牌/非 MODEL 方块）的白色线框 + 浮动文字 | `buildChunks` 显式跳过（`e.isWhiteText` 分支为空），逐帧调 `LevelRenderer.renderLineBox()` |
| `entityLabels`（蓝图里的实体）的黄色线框 + 浮动文字 | 同上，逐帧调 `renderLineBox()` |

### 预构建 VBO（不是每帧，仅内容变化时重建）

| 内容 | 机制 |
|---|---|
| 普通 MODEL 方块 | 后台线程 tessellate → 分块上传（每帧最多传一块 4096 方块），之后只调 `bpSlot.draw()` |
| 流体方块 | 同上，用静态贴图（still 帧，不做流动动画） |

### 每帧代价为何不大

Outliner 每帧的总顶点量极少（几十个框 × 每框约 400 顶点 ≈ 万级），GPU 一帧可处理百万顶点，这是零头。`specialEntries` 通常也只有几十格容器/告示牌。真正贵的是普通方块的 VBO 构建，已异步化，不影响帧率。

### 线框为什么不能做成 VBO 缓存

理论上可以，但：
1. `MultiBufferSource` API 无"保留缓冲区"机制，切换需自建 `VertexBuffer` 管理
2. 相机偏移 `box.move(camera.scale(-1))` 必须用当前帧相机，无论如何要在帧内算
3. 收益接近零（线框从来不是帧损耗来源）

## 五、原版 / Ponder 渲染特殊方块的方式（对比参考）

Ponder（Create 的预览场景系统）三层渲染：

| 类型 | Ponder 做法 | 本模组做法 |
|---|---|---|
| 普通 MODEL 方块 | `ModelBlockRenderer.tesselateBlock()` → `SuperByteBuffer` 缓存 VBO | 同左（`bpSlot` VBO） |
| 箱子/潜影盒/告示牌（有 BE） | 构造虚拟 `SchematicLevel`，动态 `new BlockEntity()`，调原版 `BlockEntityRenderDispatcher.render()` **每帧** | 白色线框 + 浮动文字，每帧，**不渲染 3D 外形** |
| 生物/实体 | `EntityType.create(nbt, level)` 创建真实 Entity，调 `EntityRenderDispatcher.render()` **每帧**，实体还要每 tick 驱动动画 | 黄色线框 + 浮动文字，每帧，**不渲染 3D 模型** |

Ponder 能渲染真实 3D 外形的代价：BE 和实体每帧都要走渲染器，大量 BE 会有持续 CPU 开销。
本模组用线框替代是有意权衡：VBO 预构建不方便运行 BER，且蓝图是静态快照，空箱子意义不大。

**SchematicLevel 关键机制**：`getBlockEntity()` 时调 `((EntityBlock) state.getBlock()).newBlockEntity(pos, state)` 动态创建空 BE，`setLevel(this)` 指向虚拟世界，使 BER 能正常取邻块信息；光照固定返回 15。

## 七、待办「线框全服可见」的真正对象：项目占地框（未做，方案待拍板）

待办 D 段原文：持有者自己的预览已做（e07 / SB-004：脱手常显、走远 / 换维度自动关）；**广播给所有人这一层未做**。用户 2026-09-15 拍板要「全服可见」。

### 与手持预览的差异

| | 手持预览 `other_` | 项目占地框 `project_preview_*` / `subproject_preview_*` |
|---|---|---|
| 生命周期 | 随手持蓝图出现 / 消失，短 | 项目存在世界数据里，长期 |
| 数据来源 | 客户端上报（C2S_PreviewUpdate） | 服务端 `ProjectData` 自有 |
| 登录全量下发 | 可有可无（下一轮上报自然补上） | **必须**（不推就永远看不到） |
| 现状 | 已有整套广播 | 只有持有者从状态包拿（`ClientProjectStatusCache:48-49` → `ClientProjectPreview` / `ClientSubProjectPreview`），**无任何广播通道** |

### 方案方向（草案，未拍板）

1. 服务端按维度把项目范围（origin / size / dimension / 阶段，可选子工程框）推给所有人：新 S2C 消息，追加在 `BlueprintNetwork.register()` 末尾，**bump mod_version**，三端一起换（T3）。
2. 增量：项目创建 / 改范围 / 删除 / 阶段变化 → 推单条；登录 / 换维度 → 按当前维度全量。
3. 客户端：独立缓存（不要混进持有者的 `ClientProjectPreview`，否则持有者开关会误关别人的框），整份替换语义（T10）；渲染做距离剔除 + 数量上限。
4. 要定：哪些阶段对外可见（规划中 / 构建中 / 已完成 / 已拆除）、私人项目是否外显、是否受 `/sbp preview` 总开关控制、颜色区分他人项目。
