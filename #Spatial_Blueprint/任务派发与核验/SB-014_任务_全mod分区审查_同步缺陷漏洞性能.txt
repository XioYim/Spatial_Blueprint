四、要做什么：按区域审查
------------------------------------------------------------
包根 src\main\java\com\xioyim\spatialblueprint\。下面按功能区域给大方向，
每区域都按同一套四类问题看：
  [同步] 客户端 / 服务端状态不一致、客户端自判而服务端不复核、缓存不失效、换维度 / 断线 / 重登不清理
  [BUG]  逻辑错误、边界条件、空值、并发 / 线程（网络线程直接动世界 / 动非线程安全集合）、资源泄漏
  [漏洞] 改包可绕过的门禁、缺归属 / 权限校验、缺尺寸 / 数量 / 频率上限、信任客户端给的数据
  [性能] 每 tick / 每帧的全量遍历、主线程大 IO、大包、无上限的缓存或集合、重复计算

A. 网络层（network\，network\s2c\，约 80 个消息类）
   - 每条 C2S 的 handle：是否 enqueueWork 回主线程；是否复核权限 / 归属 / 距离 / 维度；
     是否信任客户端给的尺寸、坐标、ID、材料表、NBT；有无频率限制。
   - 每条 S2C：encode/decode 是否对称；字符串 / 列表 / NBT 有无长度上限；客户端缓存是否整份替换（T10）。
   - register() 顺序与方向是否与 T3 一致；有无客户端类被服务端路径引用（专服类加载崩溃，T4）。
   - 大包：蓝图数据 / 库列表 / 材料表下发是否可能超包大小；有无分片。
   - 已知待办 H2（库列表全量下发、RequestBlueprintData 不查归属）不必重报，只确认现状并列出同类消息。

B. 捕获与净化（util 里的捕获 / Sanitizer / Validator，server\BlueprintValidator，空白蓝图 / 次元蓝图选区）
   - 体积上限、区块加载、领地（claim）检查是否在服务端做且不能被客户端跳过。
   - 非法方块 / 危险 NBT / 实体的净化是否每条入口都走到（捕获、上传、重新储存 VoidRecapture、force 路径）。
   - 同一概念多处判断是否一致（「同一问题两种处理 = 遗漏」）。
   - 大选区捕获是否在主线程一次性完成（卡服）。

C. 放置与撤销（util\BlueprintPlacementHandler 及相关，SBUndoCooldown）
   - 分帧 / 分批放置的中途状态：玩家下线、换维度、区块卸载、服务器关闭时是否残留或丢材料。
   - 材料扣除与放置是否原子；撤销能否被刷（复制物品 / 材料）。
   - 放置距离、维度、权限、冷却是否仅服务端判定。
   - 放置时的方块更新 / 光照 / 实体生成的性能（大蓝图一次性放置）。

D. 蓝图存储、库与上传（util\BlueprintStorage，上传界面对应的 C2S，log\）
   - 文件读写是否在主线程；文件名 / ID 是否可路径穿越；并发上传同一 ID。
   - force 上传不重算 size / materialList（已知待办，只确认），同类「信任客户端声明值」的地方列出。
   - 分片上传的超时 / 清理 / 单人并发上限（参照 K6）。
   - 槽位上限：convertCategory 等操作是否按蓝图主人判定（已知待办，找同类）。

E. 次元蓝图与材料空间（MaterialSpace，DimensionalBlueprintItem，VoidDimensionalScreen 相关消息）
   - 存材料 / 返还物品的复制与吞物风险（L2 盔甲槽、L3 堆叠上限已知，找同类）。
   - 孤儿袋、蓝图文件被删后的状态；客户端 ClientMaterialSpaceCache 何时失效。
   - VoidTeleport 的落点安全与权限（L4 已知）。

F. 工程蓝图与项目蓝图（EngineeringBlueprint*，Project*，ClientProjectPreview / ClientSubProjectPreview / ClientProjectStatusCache）
   - 按 C3 核对：项目维度门禁、阶段流转、子工程领取与占用释放、项目删除后残留物品。
   - 状态包下发时机：创建 / 改范围 / 删除 / 登录 / 换维度后客户端是否一致。
   - 只改元数据的 C2S（如 SubmitProjectChanges）是否校验归属与维度（待办已提，确认并列同类）。

G. 物品层（item\，约 13 个）
   - 客户端写 NBT 而服务端不写（L1：预览状态靠「服务端故意不写 NBT」维持，ItemSyncUtil.syncHand 会抹掉）——列出全部 syncHand 调用点与受影响字段。
   - 右键 / use 逻辑是否在两端各跑一遍产生分歧；物品 NBT 是否可被客户端伪造后被服务端信任。

H. 客户端渲染与线框（client\，client\outliner\，client\renderer\，BlueprintSelectionRenderer 2500+ 行）
   - 每帧：遍历量、对象分配、未距离剔除 / 无上限的集合（other_ 线框、specialEntries、entityLabels）。
   - VBO 槽位的创建 / 释放是否配对，换世界 / 断线 / 关闭预览时是否泄漏。
   - 客户端缓存（ClientOtherPreviewCache 等）在换维度 / 断线 / 源玩家消失时是否清理。
   - 预览广播：清除包按源玩家位置和半径下发导致残影、锁定模式丢最后一次移动、去重不比 blueprintId（服务器线框查询报告里的分析已指出，确认现状即可）。

I. 界面（gui\，约 44 个 Screen）
   - 界面上的按钮禁用 / 隐藏是否是唯一门禁（服务端无复核即为漏洞）。
   - 界面打开期间数据被服务端改变（别人删了蓝图 / 项目）时界面行为。
   - 客户端直读本地配置而非 ConfigAccess（SB-012 已改，查漏网）。
   - 每帧 render 中的重计算（排序、过滤、文本测量）与大列表。

J. 配置、命令、杂项（BlueprintConfig，config\，command\SBCommands / SBClientCommands，block\，compat\jei\）
   - 服务端配置值客户端是否拿得到且一致（ConfigAccess / 同步包）；配置保存包是否 OP 校验。
   - 命令权限等级；客户端命令是否做了本该服务端做的事。
   - 方块实体 tick 开销；JEI 兼容在无 JEI 时是否会类加载失败。
   - 登录 / 登出 / 换维度 / 换游戏模式事件里各模块的清理与重推是否齐全（SpatialBlueprintMod 事件处理）。

方法要求：
- 每条发现必须有 file:line，并说明触发条件（谁、做什么、在什么状态下）与后果。
- 区分「已确认（读代码可证）」与「疑似（需实机验证）」。
- 待办事项里已登记的问题（H2、L1–L4、force 上传、convertCategory、VoidRecapture 等）只标「已知·仍存在 / 已修」，不展开。
- 不要求穷尽，每区域优先报严重度最高的；某区域没发现也要写「已查范围 + 未发现」。
