四、要改什么
════════════════════════════════════════════════════════════════════

背景：SB-005 引入 anchor —— **一格方块**（BlockPos，整数坐标），= 第一次 [保存布局] 时范围的 min 角，此后永不改；子工程 rel 相对它，激活时 Claim 记世界 anchor（`Claim.anchorX/Y/Z`，旧 claim 用 `ProjectClaimRegistry.anchorOf` 补算）。现在客户端完全看不到它。要做三件事：状态消息带上 anchor；范围界面标题下加一行；世界里画出来。

──────────────────────────────────────────────
A. 状态消息带 anchor
──────────────────────────────────────────────

A1  network\s2c\S2C_ProjectStatusMessage.java：**末尾追加**三个字段 `boolean hasAnchor`、`BlockPos authorAnchor`、`BlockPos worldAnchor`（字段 :33-34 之后、encode :95 之后、decode :117 之后；现有 11 参构造器保留并转发 false/ZERO/ZERO，新增 14 参构造器）。
A2  network\C2S_RequestProjectStatusMessage.java sendStatus（:110-121 那段之后）：
      hasAnchor = project.size 三轴 > 0（与 ProjectData.hasAnchor() 同判据）；
      authorAnchor = project.anchor（无则 ZERO）；
      worldAnchor = 已激活且 claim != null ? ProjectClaimRegistry.anchorOf(claim, project) : authorAnchor。
    传给新构造器。

──────────────────────────────────────────────
B. 范围界面标题下一行「中心点：x y z」
──────────────────────────────────────────────

B1  gui\ProjectRangeScreen.java：构造器（:77-78 五参那个）再加 `@Nullable BlockPos anchor`（三参 / 五参旧构造器保留转发 null）；存字段。
B2  render() 里标题（:342 `titleY = cy - 130`，:363 画标题）之后、坐标行（:366）之前，加第二行居中灰字（`titleY + 12`）：
      · anchor != null（项目已有基准点）→ lang `spatial_blueprint.gui.project_range.anchor`（zh「中心点：%s %s %s」/ en "Anchor: %s %s %s"），三参 = anchor 的 X Y Z，颜色 0xFFD54F（金，与世界里的框同色）。
      · anchor == null 且两点都在 → `spatial_blueprint.gui.project_range.anchor_pending`（zh「中心点（保存后锁定）：%s %s %s」/ en "Anchor (locked on save): %s %s %s"），三参 = 当前两点各轴 min（这就是首次保存会写进去的 anchor），颜色 0xAAAAAA。
      · 两点不齐 → `spatial_blueprint.gui.project_range.anchor_none`（zh「中心点：未设定」/ en "Anchor: not set"），0xAAAAAA。
    检查 `titleY + 12` 不压到第一排坐标行 `rowY - 13`（cy + 38）：cy − 118 与 cy + 38 差 156px，没问题。
B3  gui\ProjectBlueprintScreen.java:162-165 [规划项目] 的调用：多传 `status.hasAnchor ? status.authorAnchor : null`（作者盒 anchor；范围界面编辑的是作者盒）。

──────────────────────────────────────────────
C. 世界里画中心点：一格金框 + 一条竖线
──────────────────────────────────────────────

Outliner 没有 showLine；`showCorner(slot, corner, length, sx, sy, sz)` 画的是从 corner 出发沿三轴的三条线，`sx = 0, sz = 0, sy = 1` 时就只剩一条竖线（另两条长度 0，看不见）—— 用它。参考 client\outliner\CornerOutline.java:47-53（禁区文件，只读）。

C1  client\BlueprintSelectionRenderer.java 加一个私有静态方法 `renderAnchorMarker(String slotPrefix, BlockPos anchor, int heightAbove)`：
      · 金框：`chaseAABB(slotPrefix + "_anchor_box", new AABB(ax, ay, az, ax+1, ay+1, az+1)).colored(0xFFD54F).noDepth().lineWidth(GHOST_BOX_LINE_WIDTH)`；
      · 竖线：`showCorner(slotPrefix + "_anchor_line", new Vec3(ax + 0.5, ay + 1, az + 0.5), heightAbove, 0, 1, 0).colored(0xFFD54F).noDepth().lineWidth(GHOST_POINT_LINE_WIDTH).renderPriority(2)` —— 从格顶中心往上 heightAbove 格。
    heightAbove 由调用方给：有盒子时 = 盒顶到 anchor 格顶的高度 + 4（线冒出盒顶 4 格，远处也认得出）；没盒子时 = 16。最小 4。
    颜色常量抽成 `GHOST_COLOR_ANCHOR = 0xFFD54F` 放在 :83 附近。
C2  编辑态（主手项目蓝图，`renderProjectBlueprint` :1258 那段）：从 `ClientProjectStatusCache.get()` 取状态，`status.found && status.projectId.equals(该物品 projectId) && status.hasAnchor` 时 → `renderAnchorMarker("project_range", status.authorAnchor, h)`，h 按作者盒（status.authorOrigin/authorSize）算。状态不匹配或无 anchor → 两个 slot 各 `remove` 一次。
    ⚠ 主手拿的是**未激活**手柄时作者盒与 anchor 是一回事；拿**已激活**的蓝图时编辑态也仍按作者盒画（范围界面改的是作者盒）——写进注释。
C3  预览态（`renderProjectPreviews` :2228）：`ClientProjectPreview.Range` 加 `@Nullable BlockPos anchor`（第四个分量；enable / onStatus 时从 status.worldAnchor 填，hasAnchor=false 填 null），每个开着预览且 `range.anchor != null` 的项目 → `renderAnchorMarker("project_preview_" + pid, range.anchor, h)`，h 按该 claim 盒（range.origin/size）算。预览的 anchor 用 **worldAnchor**（已激活 = 实例的基准点，未激活 = 作者 anchor）。
    ClientProjectPreview 是禁区外允许改的文件（第三节有）；enable 的调用点在 ProjectBlueprintScreen:207-210，一并传。
C4  两处 slot 前缀不同（`project_range` / `project_preview_<pid>`），互不覆盖；Outliner 条目不刷新自动淡出，disable / 换手后不必手动 remove（C2 那两句 remove 只是编辑态状态不匹配时的即时清理）。
