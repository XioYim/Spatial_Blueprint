现状（2.7.29）：工程蓝图有两条创建路，汇合在同一条 C2S 消息：
  路 A（空白蓝图）：PointSelectionScreen [创建] → CreateBlueprintScreen 选 [工程]（名字 / 时长 / 短备注 / 长备注）
       → BlueprintReportScreen（扫世界）确认 → PointSelectionScreen.startCapture("engineering") → openCreateEngineeringScreen()
       → CreateEngineeringProjectScreen(sourceId="", 名字, …)（只再填名字 + 距离；**上一页填的时长 / 备注被丢掉**）
       → C2S_CreateEngineeringBlueprintMessage → 服务端 sourceId 为空 → 现场扫世界（**不看报告选的模式，无非法方块 / 危险 NBT 检查**）。
  路 B（⌘）：PlacementScreen 手持已有蓝图 + 开着预览 → ⌘ → 直接 CreateEngineeringProjectScreen(sourceId=蓝图 id, …)
       → 同一条消息 → 服务端 BlueprintStorage.load 复制源文件（**不经任何报告、不净化**）。
  另有一个「工程私有距离」：创建页距离框（默认 128）→ 消息 maxDistance → 文件 data.maxDistance + 物品 NBT engMaxDistance
       → checkProjectBounds 的 TOO_FAR（玩家到起 / 终点取近 > maxDistance 就不让开预览 / 放置）。

用户拍板四件事：
  1. **删掉工程私有距离**，只留全局配置 `previewDistance`。服务端本来就有 `BlueprintValidator.validatePlacementDistance`（到放置目标点 ≤ previewDistance + 512，工程蓝图也过），所以服务端只删 TOO_FAR 分支、不加新东西；客户端 [开启预览] 的置灰改为「min(到起点, 到终点) > previewDistance（服务端镜像值）」。
  2. **⌘ 接内容检测报告**：点 ⌘ 先看一份「这份蓝图里有什么非法 / 危险内容」的报告（复用上传流程的 `BlueprintSanitizer.scanBlueprintData` + `S2C_UploadReportMessage` + `UploadReportScreen`），确认后才进创建页。
  3. **创建页重做**，两条路共用：名称 / 构建时长 / 简单备注 / 详细备注 / 只读维度·起点·终点·尺寸；没有距离框。路 A 把 CreateBlueprintScreen 填的时长 / 备注带进来预填。
  4. **服务端两条分支都按报告页选的模式处理**（与 CaptureAreaMessage 同一套语义）：复制分支对副本跑一遍 BlueprintSanitizer；扫描分支补上与捕获路相同的预扫 / 净化 —— 这就把待办里「工程蓝图扫描新区域无非法方块检查」那条口子闭合了。

做完之后的链路：
  路 A：… → BlueprintReportScreen（扫世界，三个模式按钮）确认 → 新创建页（预填名字 / 时长 / 备注）→ 消息(sourceId="", captureMode=选的) → 服务端扫世界，按模式预扫 / 净化。
