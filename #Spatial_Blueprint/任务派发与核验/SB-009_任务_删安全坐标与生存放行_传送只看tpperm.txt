二、目标与背景
────────────────────────────────────────────────────────────────────────

现状（2.7.27 源码）：工程蓝图的 [Tp] 传送在服务端 `C2S_EngineeringTeleportMessage.handle` 里过两道门：
  第一道 `TeleportPermissions.canTeleport(player)` —— OP(2) / 创造模式 / `/sb tpperm grant` 名单，与次元蓝图传送共用；
  第二道 按蓝图的「生存放行开关」`allowSurvival` —— 非创造玩家必须该工程的开关为开，否则「管理员已关闭生存模式传送」；
  落点若设了「安全传送坐标」就传到那个点，否则传到绑定工程起点 / 终点里离玩家近的那个。
第二道门与安全坐标由 OP 在 `SafeCoordScreen`（蓝图库 → 工程 Tab → 已选中行再点一下）设置，存 `SBSafeCoordData`（SavedData，键 `sb_safe_coord`），
经 `C2S_SafeCoordMessage` 上行、随 `S2C_LibrarySyncMessage` 的 5 个 safe 字段下行到客户端做 tooltip 与界面初值。

用户决定：**这套东西整体删掉**。工程蓝图传送与次元蓝图传送用同一套判定 —— 只看 `TeleportPermissions.canTeleport`；落点固定为起点 / 终点取近。
做完之后：
  1. 生存 / 冒险玩家只要在 tpperm 名单里就能传，不再有按蓝图的第二道门；OP 生存模式不再被自己关的门挡住。
  2. 蓝图库工程 Tab 里已选中行再点击 = 取消选中（与其他 Tab 一致），不再弹「设定安全坐标」页；名称 tooltip 不再有「点击设定安全传送坐标」行。
  3. `SBSafeCoordData` / `SafeCoordScreen` / `C2S_SafeCoordMessage` 三个类不存在；`BlueprintSummary` 少 5 个组件；`S2C_LibrarySyncMessage` 每条摘要少 1 bool + 3 int + 1 bool。

不要做的：
- 不动 `TeleportPermissions` / `S2C_TeleportPermMessage` / `ClientTeleportPermCache` / `C2S_VoidTeleportMessage` / `SBCommands`（tpperm 那套本来就对，不要「顺手优化」）。
- 不给 OP 生存模式加任何新豁免 —— `canTeleport` 已经给 OP 放行，第二道门删掉就够。
- 不 bump `mod_version`、不构建 jar、不部署（主会话统一处理：本任务是 wire 变更，主会话会把 2.7.27 → 2.7.28 并三端一起换）。
- 不去清理存档里已有的 `data\sb_safe_coord.dat`（SavedData 只在被 `computeIfAbsent` 请求时加载，类删了那个文件就是死数据，无害；报告「风险」段提一句即可）。
- 不动 `EngineeringBlueprintScreen`（:216 那段注释「OP / 创造模式 / 被 /sb tpperm 授予，与次元蓝图共用同一套判定」本来就是删完之后的事实）。
- 不改 `spatial_blueprint.gui.engineering.btn.tp.no_op` 等其他 lang 键的文案。
