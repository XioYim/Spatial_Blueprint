背景事实（已核实，不必再推导）：
- 版本：`gradle.properties` 当前 2.7.10，尚未构建部署，所以本任务的 wire 改动并入 2.7.10，不 bump。
- `S2C_ProjectStatusMessage.EntryStatus` 现有字段：index / label / note / sizeX,Y,Z / blockCount / completed / cooldownRemainSec / requiresEntry / prereqMet / animDuration / creatorName / createdAt / absMin / absMax（e18 加的末尾五项）。`absMin/absMax` 是子工程包围盒的绝对两角（未激活按作者参考系），预览线直接用它。
- `ProjectData.EntryData` 有 `color`（ARGB，Alpha 固定 255，创建时按调色板循环分配）和 `filename`（`{engUuid}.litematic`），客户端目前都拿不到。
- 状态包到达的客户端入口：`ClientProjectStatusCache.onReceive(msg)`（它已调用 `ClientProjectPreview.onStatus(msg)`）。
- 项目预览的生命周期：`ClientProjectPreview` 存 projectId → Range，渲染器 `renderProjectPreviews` 每帧按维度 / 距离自动关，`ClientProjectPreview.onClientTick` 每 100 tick 查背包、蓝图不在了就 `enabled.keySet().removeIf(...)`。
- Outliner：`chaseAABB(slot, aabb).colored(argb).lineWidth(w)` 不带 `.noDepth()` 就是深度测试（`AABBOutline` 按 `params.isNoDepth()` 选 `outlineSolid()` / `outlineSolidNoDepth()`）；不带 `.withFaceTextures(...)` 就只有 12 条边。条目不再每帧刷新会自动淡出，关预览不用手动 remove。
- 客户端拿子工程的 BlueprintData：`ClientBlueprintCache.get(engId)`；没有就 `BlueprintNetwork.CHANNEL.sendToServer(new C2S_RequestBlueprintDataMessage(engId))`，服务端 `BlueprintStorage.load` 会到 `projects/<pid>/` 下找 `{engId}.litematic`，用 `sendBlueprintTo` 分片推回，`ClientBlueprintCache.isDownloading / isFailed / getFailReason` 可查进度。请求有 500ms 冷却。
- 材料清单结构：`MaterialList.blockCounts`（LinkedHashMap<String,Integer>，键 = 物品 id 或带 NBT 的复合键）+ `keyTags`（复合键 → 规范化 NBT，只含带 NBT 的条目）；`MaterialList.copy()` 深拷贝。`PlacementScreen` 的材料面板编辑规则：✚ 打开 `MaterialItemPickerScreen(parent, AddHandler)` 新增；左键格子改数量（弹小输入框，>0 才写）；右键格子弹删除确认。服务端整份覆盖写法见 `C2S_SaveMaterialListMessage.handle`（清空 blockCounts / keyTags 再 putAll）。
- 服务端删除子工程的三清顺序（照 `C2S_DeleteSubProjectMessage`）：`ProjectProgressData.forgetEntry(taskSetIds, index)` → `ProjectStorage.deleteEntryFile(projectUuid, filename)` → `project.entries.remove(entry)`；有别的条目 `requiresEntry` 指向它则拒。
- 服务端重排 / 重编号（照 `C2S_SubmitProjectOrderMessage`）：按顺序重排 entries → 位置重编号 1..N → 按旧→新映射重写各条 `requiresEntry` → `ProjectStorage.saveProject` → `C2S_RequestProjectStatusMessage.sendStatus(player)`。门禁：OP + 主手项目蓝图 + 项目存在 + `ProjectClaimRegistry.hasAnyClaimForProject(pid)` 为 false（有占用整单拒，键 `spatial_blueprint.message.project.order.activated`）。
- 横幅规则（T9 / C1）：失败一律 `S2C_OperationResult(false, key, detailKey, args)`，主键无参、参数走 detail；界面已实现 `ErrorToastSupport`。
- 迷你行几何：`MINI_SZ = 18`，按钮间隔 2，从 `listX` 起排，最后一个迷你按钮后 +6 放文本按钮 [提交修改]；面板宽 364。六个迷你按钮 = 6×18 + 5×2 = 118px，后面放 [提交修改] 宽度够，不需要改面板。
