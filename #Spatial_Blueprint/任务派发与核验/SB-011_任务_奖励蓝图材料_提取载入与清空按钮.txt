二、目标与背景
────────────────────────────────────────────────────────────────────────

现状：
- 奖励蓝图 = OP 用空白蓝图 [(OP)奖励蓝图] FORCE 捕获的投影类蓝图，`category = "reward"`，创建时 `materialList = new MaterialList()`（空），放置免费（`PlaceBlueprintMessage` :361：`skipConsume = opBypassCapture && !(isReward && 清单非空)`）。OP 想收料就事后自己往清单里加。**这个默认不变，本任务不碰 `CaptureProjectionMessage`。**
- 奖励蓝图材料的唯一编辑入口：放置界面材料面板（`gui/PlacementScreen`），`canEditMaterials()`（:277，创造 OP；奖励蓝图虽 FORCE 也放行）。底排三个 18px 方形迷你按钮（手动 render + 手动命中，不入 renderables）：`✚ 新增`（物品选择器）/ `✎ 快捷存入`（仅生存，与本任务无关）/ `⎙ 保存`（`C2S_SaveMaterialListMessage`，服务端逐条 `MaterialKey.idOf` + `BlueprintSanitizer.isIllegalBlockId` 拒非法，拒了就 `pushData` 回推真实清单）。增删改都只动本地副本 `localMats`，⎙ 才写盘。
- `MaterialList.fromBlueprintData`（`util/MaterialList.java` :53）：三个方块表计数 → 批量转换 / 替换表 / 免费方块 → 实体与展示框内物品也计入；**不过滤非法方块**。奖励蓝图是 FORCE 捕获，命令方块 / 刷怪笼 / 展示框里的非法物品会原样进数据。

用户要的：在 `⎙ 保存` 左边加两个**奖励蓝图专属**迷你按钮（只在 `isRewardBlueprint() && canEditMaterials()` 时出现）：
  ✎ 提取并载入材料 —— 按这份蓝图的方块数据生成材料清单，剔掉非法方块，载入。
  ✖ 清空全部材料 —— 清单清空（= 放置免费）。

设计（用户已拍板）：
- **两个动作都在服务端做、直接写盘、回推数据**，不经 ⎙。理由：替换表（`GeneratedSubstitutionsConfig`）/ 批量转换（`BulkMaterialConverter`）/ 非法表都是服务端 COMMON 配置，客户端本地那份在专服上可能不一样（T8），生成必须服务端算；清空为对称也走服务端。一条新 C2S、两个 mode。
- 非法过滤与 ⎙ 保存路径**同一个判定**：`MaterialKey.idOf(key)` 还原注册 id → `BlueprintSanitizer.isIllegalBlockId`。报告页标危险的这里必剔。过滤作用在生成完成后的最终清单上（替换 / 批量转换之后），连 `keyTags` 里对应的键一起删。
- 点这两个按钮时**丢弃面板未保存的本地改动**（`localMats = null`），回推到达后面板显示服务端那份。tooltip 写明「会覆盖未保存的改动」。
- ✖ 清空加一道确认（与面板单条 [删除] 的确认覆盖层同款样式：一行提示 + [清空][取消]），误点不丢 OP 手调的清单。✎ 提取不用确认（提取错了再清空 / 再提取即可）。
- 服务端只对 `data.category == "reward"` 放行，其它分类回横幅拒。

不要做的：
- 不动 `CaptureProjectionMessage`（创建默认仍空清单）、不动 `C2S_SaveMaterialListMessage` 的逻辑（只允许改它的 javadoc 里「唯一写入路径」那句）、不动 `PlaceBlueprintMessage` 扣料逻辑、不动 `MaterialList.fromBlueprintData` 本身（过滤是它之外的一个新方法）。
- 不给其它分类的蓝图显示这两个按钮；不在生存模式显示。
- 不 bump `mod_version`、不构建、不部署（主会话统一处理：本任务 wire 变，与 e50 / e51 一起 bump 2.7.33）。

4.1 `util/BlueprintSanitizer.java` —— 新增过滤方法
  `public static int removeIllegalMaterialsInPlace(MaterialList ml)`：遍历 `ml.blockCounts` 的键，`MaterialKey.idOf(key)` 还原注册 id，`isIllegalBlockId` 命中的从 `blockCounts` 与 `keyTags` 里都删掉；返回删掉的条数（日志用）。放在 `isIllegalBlockId` 附近。
  为什么：与 `C2S_SaveMaterialListMessage` :92 的判定完全一致，两处不能各写一套。

4.2 新消息 `network/C2S_RewardMaterialsMessage.java` + 注册
  字段：`String blueprintId`（utf 64）、`int mode`（`MODE_GENERATE = 0` / `MODE_CLEAR = 1`，`writeVarInt`）。
  handle（enqueueWork）：
    a) `player == null || blueprintId.isEmpty()` → return；`!player.hasPermissions(2) || !player.isCreative()` → 横幅 `spatial_blueprint.message.reward_materials.need_op`（无参主键，T9）后 return。
    b) `data = BlueprintStorage.load(blueprintId)`，null → 横幅 `spatial_blueprint.error.no_blueprint_data`；`!"reward".equals(data.category)` → 横幅 `spatial_blueprint.message.reward_materials.not_reward`。
    c) `MODE_GENERATE`：`ml = MaterialList.fromBlueprintData(data)`；`removed = BlueprintSanitizer.removeIllegalMaterialsInPlace(ml)`；`data.materialList = ml`。
       `MODE_CLEAR`：`data.materialList = new MaterialList()`，`blueprintName` 照 `C2S_SaveMaterialListMessage` :105-108 那样填。
       其它 mode → return。
    d) `BlueprintStorage.save(UUID.fromString(blueprintId), data)`（try/catch 与 Save 消息同款；失败横幅 `spatial_blueprint.error.blueprint_load_error` 或现有的保存失败键，先看 Save 消息用的哪个，跟它一样）。
    e) 回推：`BlueprintNetwork.sendBlueprintTo(player, blueprintId, data)`（T10：只能走这条）。
    f) 聊天栏：GENERATE → `spatial_blueprint.message.reward_materials.generated`（参数：条目数、剔除数）；CLEAR → `spatial_blueprint.message.reward_materials.cleared`。`SpatialBlueprintMod.LOGGER.info` 一行 `[Reward] <玩家> generate/clear id=… entries=… removed=…`。
    ⚠ 横幅一律 `S2C_OperationResult(false, key)`：它的失败分支不关界面（`C2S_SaveMaterialListMessage` :86-88 的注释说明了成功分支会关 PlacementScreen，所以**成功不要发 S2C_OperationResult**，用聊天栏）。
  `network/BlueprintNetwork.java`：`register()` **末尾**追加 `c2s(C2S_RewardMaterialsMessage.class, …)`，其它一行不动（T3）。派发时末尾是 `C2S_SafeCoordMessage`（e51 加的），本条接在它后面。
