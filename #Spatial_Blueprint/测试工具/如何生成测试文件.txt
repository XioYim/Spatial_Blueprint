# Spatial_Blueprint · 如何生成测试文件

测试夹具生成脚本都在 `C:\Users\Yim\AppData\Local\Temp\opencode\`（node 跑，不用 python）。
注意：命令里别出现中文路径，含中文路径的脚本一律落成 .js 文件再跑（见 K2）。

1. fill-lib.js —— 蓝图库滚动测试（172）凑 200+ 条目
   node fill-lib.js test fill    往 1.20.1 Forge 实例 config/spatial_blueprint 里最小那份蓝图复制 220 份
   node fill-lib.js test clean   删掉 test_scroll_ 开头的复制品（测完必须清）
   test = 1.20.1 Forge 实例，pack = 整合包实例。
   注意：复制品文件名最后一段必须是真 UUID，否则库扫描（listSummaries）直接跳过，一条都看不到。

2. gen-bad-files.js —— 坏文件（173/174）
   node gen-bad-files.js
   往测试实例 schematics/ 写 4 个：bad_nogzip.litematic / bad_noregions.litematic / bad_nogzip.schematic / bad_nodims.schematic。
   无参数，重复跑直接覆盖。

3. gen-entity-files.js —— 带实体文件（175~178）
   node gen-entity-files.js
   往测试实例 schematics/ 写 3 个：test_entity.litematic / .schem / .schematic。
   内容都是 3x3x3（石头地板 y=0 + 后墙 z=0，画挂 (1,1,1) 朝北、展示框挂 (0,1,1) 朝北）。
   NBT 手写要点：ListTag 元素是裸 payload（不带类型+名字头），写错就是整包解析失败。
   改完生成器先跑 nbtcheck.js 自验：node runcheck.js（结构对 + leftover bytes: 0 才算过）。

4. nbtcheck.js —— 通用 NBT 结构 dump（排错用）
   直接传文件路径（runcheck.js 包了一层，免得命令行写中文路径）。
