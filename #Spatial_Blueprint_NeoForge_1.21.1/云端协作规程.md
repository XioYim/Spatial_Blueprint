# 云端协作规程（仅用于 1.21.1 迁移）

> 建立：2026-09-29 14:40:00（用户逐条拍板）。适用范围：`neoforge-1.21.1` 分支及其任务分支；1.20.1 线（`forge-1.20.1`）不用本规程。
> 本文件与 `记忆与注意事项\项目记忆.md` 冲突时以本文件为准，并回去改项目记忆。

**本地会话的默认身份**：用户在本地说「执行 SBN-00N」时，本地会话就是辅助 AI，照第三节走；想记的东西只写在报告「建议记入」段，由云端问过用户后再写。

## 二、分支

- **集成分支** `neoforge-1.21.1`：只接收验收通过的合并，任何一方都不直接往上提交零散改动（本规程与 P0 文档除外）。
- **任务分支** `task/SBN-00N`：云端从集成分支拉出，第一个提交是 TASK 手册；辅助 AI 在同一分支上执行、推送；验收不通过就在同一分支上追加补丁 TASK（`SBN-00Na`、`SBN-00Nb`…）。
- **合并**：验收通过后由云端 `git merge --no-ff task/SBN-00N` 进集成分支并推送；云端推不了集成分支时，在验收记录里写「PASS，待合并」，由用户在 GitHub 上开 PR 合并，或下次本地会话按用户指令合并。
- **轮流**：任务分支同一时刻只有一方在写。TASK 推送之后云端不再往这个分支提交，直到辅助 AI 推回报告；辅助 AI 推完报告后不再提交，直到下一份 TASK / 补丁。

## 三、一轮循环

**云端：派发**
1. 从集成分支最新提交拉 `task/SBN-00N`。
2. 写 `任务派发与核验\SBN-00N_任务_<简述>.txt`。第一段写备份命令，第二段只给 `项目记忆.md` 路径；下面再写目标、允许修改的文件清单、已定方案（能 javap 的都先取证）、验收标准、测试分类（第四节）、报告模板，并写明「以源码为准，与任务书有出入时在报告里指出」。
3. 提交并推送任务分支，告诉用户：「去本地说『执行 SBN-00N』」。

**本地：执行**（用户在本地说「执行 SBN-00N」）
1. `git fetch origin --prune`；工作区不干净就停下问用户。找任务分支：先找 `origin/task/SBN-00N`；没有就逐个远程分支查谁含 `任务派发与核验/SBN-00N_任务_*.txt`（`git ls-tree -r --name-only <分支>`），正好一个就用它（云端推不了 `task/` 名时会用自己的分支名）；零个或多个就停下问用户。切过去（首次 `git switch -c <本地名> origin/<分支>`），`git pull`。之后提交都推回这个分支。
2. 读 TASK → 按第一段备份 → 按第二段接入 → 执行。
3. 验证：编译（`JAVA_HOME` = Zulu 21，`compileJava --rerun`）、GameTest、TASK 要求的起服测试。部署前 bump `mod_version`（末位 +1，到 9 进位），三个测试目录的旧 jar 直接删除，逐个比 SHA。
4. 同步：`测试清单.txt`（自动测的结果 + 手测步骤）、`开发日志.md` 文末追加 `## SBN-00N 执行记录`、通用教训（第五节）。
5. 收集证据到 `任务派发与核验\SBN-00N_证据\`（第六节），写 `SBN-00N_报告.txt`。
6. `git add` 只加 TASK 允许清单内的文件 + 报告 + 证据 + 同步过的交接件；提交并推送任务分支。对用户说一句：「已推送，去云端说『验收 SBN-00N』」，并列出需要用户手测的条目。

**云端：验收**（用户在云端说「验收 SBN-00N」）
1. `git pull`；看 `git diff neoforge-1.21.1...task/SBN-00N`。
2. **不信任报告自述**：自己在云端重新编译（不加 `--offline`）、能跑的 GameTest 自己跑一遍；文件清单用「允许清单 vs 实际改动」两向比对；逐条核对报告里的「主张 + file:line」。修 bug 的任务 / 补丁再做一次变异复核：临时关掉修复，确认新断言转红，再还原（记忆 K7）。
3. 写 `任务派发与核验\SBN-00N_验收.txt`：PASS / 有修正 PASS / 不通过，逐条理由。
4. 通过：合并（第二节）→ 开发日志主序列追加 `e<N>` → 报告里的「建议记入」逐条问用户，点头后写进 `记忆与注意事项\` 或 `通用经验\` → 提议改待办。不通过：同一分支写补丁 TASK，回到「本地：执行」。

## 四、测试分类

测试清单里每组分两段：

- **【自动】辅助 AI 自己测**：编译与警告数、GameTest（假玩家 + 往事件总线 post 真事件，断言副作用）、三端部署 SHA、专服起停（看加载日志、报错、`stop` 正常退出）、TASK 指定的服务端行为。结果当场写进清单。
- **【手测】需要用户进游戏**：界面、渲染、手感等看画面的东西。辅助 AI 写成能照做的步骤（前置 → 操作 → 预期），用户测完回一句结果，辅助 AI（或下一次本地会话）再把结果写回清单并推送。

辅助 AI 写测试清单不用另问：TASK 里写明的范围就算用户授权；范围外的改动写在报告里提议。

## 五、通用教训同步（三方比对）

- **仓库副本**：`#Spatial_Blueprint_NeoForge_1.21.1\通用经验\Mod开发与迁移_通用铁律经验教训.md`，只对本 mod 生效（只由本项目的文档引用）。云端读它、只往里追加，不改旧条。
- **基线**：上次同步后的副本内容 = `git show <上次同步提交>:<副本路径>`，同步提交记在本节末尾的表里。

辅助 AI 每轮执行都要同步一次：
1. 取基线 B、原件 A、副本 C。
2. C 比 B 多出来的条目（云端新追加的）→ 追加进 A。
3. A 比 B 变了的部分（其他项目改的）→ 让 C 与 A 一致。
4. 同一条在 A、C 两边都改过 → **不合并**，在报告「教训同步冲突」段列出原文两版，交给云端决定。
5. 写完后 A 与 C 应逐字相同（冲突条目除外）；在下表追加一行，同步提交就是本轮推送的那次提交。

## 六、证据目录

`任务派发与核验\SBN-00N_证据\` 下放纯文本（UTF-8），单个文件不超过约 200 KB，长日志只截相关段并注明截取范围：

| 文件 | 内容 |
|---|---|
| `编译.txt` | 编译命令 + 输出尾部（`BUILD` 行与全部警告行，警告计数用 `源文件:行号:`） |
| `GameTest.txt` | 运行命令 + 通过 / 失败列表 |
| `改动清单.txt` | `git diff --name-status neoforge-1.21.1...HEAD` 与允许清单的两向比对 |
| `部署.txt` | 构建 jar 名 / 大小 / SHA256 + 每个部署点的 SHA，以及删掉的旧 jar |
| `服务端.txt` | 起服到 `Done` 与 `stop` 之间的本 mod 相关日志、全部 ERROR / WARN 行 |
| 其他 | TASK 要求的专项输出 |

## 七、云端会话没有本机的全局约定，这里摘最要紧的几条

- 始终用中文回复。时间一律 `YYYY-MM-DD HH:mm:ss`。
- 默认一切都是服务器级别；改任何东西先问一句：客户端和服务端会不会不同步？
- 交接件只追加、不重写已有内容。待办事项由用户维护，AI 只提议；新增记忆先问用户，一条 = 一句话要点 + 开发日志编号。
- `待办事项.html` 直接读 HTML 源码（本机的 `html2text.ps1` 云端没有）。
- 上下文到 60% 就写开发日志、更新 `项目记忆.md` 环境现状，然后开新会话。
- 报告禁止代码块，只给「主张 + file:line」。
