## 二、两种工作模式

### A. 云端 + 本地（规程原样）
用户在本地说「执行 SBN-00N」→ 你按规程第三节「本地：执行」走；验收由云端做；你不写 `记忆与注意事项\`、不合并集成分支、不改 `待办事项.html`。

### B. 只有本地一个会话（本文件重点）
你同时是「主会话」和「辅助 AI」。仍然走同一套循环，但**验收必须像别人验收一样冷酷**——不许拿自己的报告当证据：
1. **规划 / 派发**：读迁移计划书对应阶段 → 取证（`git show origin/forge-1.20.1:<路径>` 读源码；javap 看 1.21 API，见第四节）→ 写 `任务派发与核验\SBN-00N_任务_<简述>.txt`（格式照已有任务书：备份、接入、背景、允许修改清单、已定方案、取证 Jxx、测试 A/H、验收标准 V、报告模板）→ 从集成分支拉 `task/SBN-00N`，任务书作第一个提交并推送。
2. **执行**：切到任务分支，只改「允许修改清单」里的文件；写报告与证据；推送。
3. **验收**（换一个「心态」：你在审别人的活）：按第三节配方逐项做，写 `SBN-00N_验收.txt`。可能的话让另一个 Claude 会话（或子代理）做验收，独立性最好；做不到就严格按配方，尤其**变异复核**不能省。
4. **合并 + 交接件**：`git merge --no-ff task/SBN-00N` 进集成分支并推送；按第三节末尾「合并后清单」更新文档。
5. **问用户**：新记忆（K / C 条）、待办事项改动、`测试清单.txt` 的非验收写入、saveMode 这类行为取舍，一律先在对话里说清再写。

## 七、易踩的坑（最要紧的，全文在 `注意事项_分类.md`）

- 改任何东西先问：客户端和服务端会不会不同步？默认一切服务器级别。
- **警告基线 0**（K1、K20）；`.java` 不用 PowerShell 文本命令读写（K2）；git 输出含中文按字节落地（K15）。
- 修 bug / 补测试必须**变异复核**（K7）；GameTest 里的「坏数据」别假设 `BlueprintData.deserialize` 会抛（K26）。
- **C2S 解码按客户端计数分配内存前先夹上限**（K13、K14）。
- 分边：公共包 0 处 `net.minecraft.client`；专服加载客户端类被 RuntimeDistCleaner 直接拒（**仍存在**，K29）；客户端缓存类保持纯逻辑（K30）；验证客户端边界读 `.class` 字节，别 `Class.forName`（K33）。
- 存盘写成 ListTag 的表不用 HashMap（K25）；配置热加载 `acceptConfig` + `afterReload`（K22）；GameTest mock 玩家登录只兜 `UnsupportedOperationException`（K21）。
- 顶点 API：`addVertex` 只有 float 重载（K32）；渲染任务手测靠调试驱动 + 命令（C31）。
- 蓝图物品数据一律自定义组件、只存引用（D1）；组件取出来是副本，改完必须写回。
- 新记忆先问用户；`待办事项.html` 用户维护，只提议；`测试清单.txt` 写前先问（验收归档与辅助 AI 在 TASK 范围内例外）；开发日志只追加。
