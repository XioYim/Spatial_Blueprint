## e01 · P0：NeoForge 1.21.1 骨架 + 交接件 + 仓库布局 [已完成 · 待实测] · 2026-09-29 14:06:00

**起因**：用户要求 Spatial Blueprint 同时支持 Forge 1.20.1 与 NeoForge 1.21.1，并想用云端会话（需要 GitHub 仓库）推进迁移。

**做法**：
- 仓库：1.20.1 线全部未提交改动先提交为 `09c8b7f` 推到 `XioYim/Spatial_Blueprint` 的 `main`（私有）；1.21.1 线是同仓库的 `neoforge-1.21.1` 分支，本机克隆到 `D:\Mods\Spatial_Blueprint_NeoForge_1.21.1`（用户拍板：同仓库新分支，不另建仓库、不做多模块）。
- 分支内删掉 1.20.1 的 `src\main\java`、`mods.toml`、`libs\`（JEI 1.20.1 jar）、`#Spatial_Blueprint\` 文档与旧 `CLAUDE.md`；1.20.1 源码随时可从 `D:\Mods\Spatial_Blueprint` 或 `git show origin/main:<路径>` 读。
- 构建：照搬 HD 1.21.1 线的 `build.gradle` / `settings.gradle` / wrapper（ModDevGradle 2.0.147、Gradle 9.2.1）；`gradle.properties` 按 SB 改（NeoForge 21.1.252、Parchment 2024.11.17、`mod_version=3.0.0`、同 modid / 包根）。新写 `src\main\templates\META-INF\neoforge.mods.toml` 与最小主类 `SpatialBlueprintMod`。
- 资源：`assets\` 原样带过来；`data\spatial_blueprint\recipes` → `recipe`，`blank_blueprint.json` 的 result 从 `item` 改 `id`（1.21 配方格式）。
- 交接件：按 `新项目骨架\新项目部署方案.md` 部署；填了根 `CLAUDE.md`、`项目记忆.md`（命令表 / 环境现状 / 派任务表）；迁移计划书复制进来并补「拍板记录」（仓库、D1 组件只存引用、D2 方块级兼容；D3～D7 暂定）；新建 `功能联动手册.md`。

**坑**：
- 1.20.1 线的 `gradle.properties` 写着本机代理 `127.0.0.1:10808`，云端会话没有这个代理，那边在云端构建会连不上。本机用户级 `~\.gradle\gradle.properties` 已有同样的代理，所以 1.21.1 线不再在项目里写代理。
- 部署脚本里的记忆目录名按骨架规则只替换 `: \ _`，Claude Code 实际目录名还会把 `.` 换成 `-`；以实际生成的目录为准。

**有意不改**：待办事项.html 仍是骨架示例，内容由用户定（本轮只在对话里提议）。

影响面：只涉及新分支与新目录；1.20.1 线只多了一次提交和远程仓库。验证：`.\gradlew.bat build --offline --rerun-tasks`（JAVA_HOME = Zulu 21）BUILD SUCCESSFUL、0 条警告；`build\libs\spatial_blueprint-3.0.0.jar` 解包确认 `neoforge.mods.toml` 占位符全部展开、`recipe\blank_blueprint.json` 在内。未 runClient / runServer（骨架没有注册内容，等 P2 再冒烟）。
