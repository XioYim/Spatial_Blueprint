### T1 · 示例铁律：客户端展示必须走服务端下发

> （示例条目。新项目删掉本节示例，按此格式写自己的第一条铁律。）

客户端拿来**展示**的数据，一律读服务端下发的值，不读本地配置。读本地只允许两种例外：纯外观项、无服务端的单机模式——例外必须在条目里写明。

| 场景 | 做法 |
|---|---|
| 列表候选（如配置名、等级名） | 服务端下发，客户端只渲染 |
| 开关 / 阈值 | 服务端权威，客户端不许有自己的默认值覆盖 |

```
grep -rn "getLocalConfig(" src/<客户端目录>/
```

上面这条命中即缺口（除非该处有注释说明为什么本地是对的）。

### K1 · 本线 javac 警告基线 0：泛型配置项登记不用裸数组

`compileJava --rerun` 的警告基线是 **0**（计数用「源文件:行号:」，中文系统输出「警告 / 注」）。`new ModConfigSpec.ConfigValue[]{...}` 这类裸泛型数组会让 javac 打 unchecked 注，破基线；登记一组 `ConfigValue<List<String>>` 用 `List.of(...)` 迭代（`config\ConfigRegistry`）。日志 SBN-001 执行记录、e03。

### C1 · 列表配置启动时的 correction WARN 是既有行为，别当 bug 修

启动日志里 `Incorrect key … was corrected … to its default` 这类 WARN 来自 `define(String, List)` 列表项的校验，与 Forge 1.20.1 源码逐字一致；文件没被手改时值不变。要根治得改 `defineListAllowEmpty` 并改字段类型（行为变更，待拍板）。日志 SBN-001 执行记录、e03。

### C2 · GameTest 日志只有批次级结果，逐条证据数注解

`runGameTestServer` 只打印 `Running test batch … (N tests)`、`[++++]`、`All N required tests passed`，不逐条列用例名。要逐条对照就 grep 测试类里 `@GameTest` 注解的实数（别把 import 行算进去），与 N 一致即全部通过。日志 SBN-001 执行记录、e03。
