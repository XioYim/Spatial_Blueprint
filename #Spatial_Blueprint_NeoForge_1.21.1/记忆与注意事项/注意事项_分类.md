### T1 · 示例铁律：客户端展示必须走服务端下发

> （示例条目。新项目删掉本节示例，按此格式写自己的第一条铁律。）

客户端拿来**展示**的数据，一律读服务端下发的值，不读本地配置。读本地只允许两种例外：纯外观项、无服务端的单机模式——例外必须在条目里写明。

| 场景 | 做法 |
|---|---|
| 列表候选（如配置名、等级名） | 服务端下发，客户端只渲染 |
| 开关 / 阈值 | 服务端权威，客户端不许有自己的默认值覆盖 |

```
grep -rn "getLocalConfig(" src/<客户端目录>/
```

上面这条命中即缺口（除非该处有注释说明为什么本地是对的）。

### K1 · 本线 javac 警告基线 0：泛型配置项登记不用裸数组

`compileJava --rerun` 的警告基线是 **0**（计数用「源文件:行号:」，中文系统输出「警告 / 注」）。`new ModConfigSpec.ConfigValue[]{...}` 这类裸泛型数组会让 javac 打 unchecked 注，破基线；登记一组 `ConfigValue<List<String>>` 用 `List.of(...)` 迭代（`config\ConfigRegistry`）。日志 SBN-001 执行记录、e03。

### K2 · .java 不用 PowerShell 文本命令读写

`Set-Content -Encoding UTF8`（PS 5.1）写 .java 会带 BOM → javac 报「需要 class、interface、enum 或 record」一片；`Get-Content` 默认按 GBK 读 UTF-8 文件，再写回会把中文变乱码并截断。改 .java 一律用 Edit / Write 工具（与「含中文 .ps1 要带 BOM」正相反）。日志 SBN-002 / SBN-002a 执行记录、e04。

### K3 · 工作区可能被旧版本回写：脏文件先 stash 取证，不丢弃

2026-09-29 15:22:13 本地工作区 4 个文件被写回 SBN-001 之前的内容（逐字等于 `e97d824`），原因未明（当时查无编辑器 / IDE 进程）。开工先 `git status`；出现说不清来源的脏文件，先对照提交确认内容、记 mtime，再 `git stash push -m <说明>` 保留，不 restore、不提交。`stash@{0}` 保留到原因查明。日志 SBN-002 执行记录、e04。

### K4 · 云端环境网络必须是 Full，改了只对新会话生效

云端会话在 Trusted 网络下，`maven.neoforged.net`、`maven.parchmentmc.org`、`libraries.minecraft.net`、`piston-meta.mojang.com` 全部 403（`services.gradle.org` 通），gradle 构建必失败。改法：桌面版 Code 标签页**新建会话** → 输入框旁的 Local / Cloud 选择器 → Cloud 分区悬停环境（Default）点齿轮 → Network access 改 Full 保存（网页 claude.ai/code 同理）。**只对新会话生效**。云端自带 OpenJDK 21 与 Gradle；仓库里 `gradlew` 没有可执行位，Linux 下用 `bash gradlew`。日志 e03、e05。

### K5 · 证据里打印 NBT 用 NbtUtils.prettyPrint，别用 structureToSnbt

`NbtUtils.structureToSnbt` 是「结构模板导出」格式，会给任意输入注入顶层 `data` / `palette` 字段；拿它打印物品 / 方块实体 NBT 会看到并不存在的键（SBN-002 / 002a 证据里把这两个键注成了「1.21 方块实体字段」，是错的）。打印一律 `NbtUtils.prettyPrint`。日志 SBN-003 执行记录、e06。

### K6 · DFU optionalFieldOf 值等于默认时省略字段

DFU 8.0.16 的 `optionalFieldOf(name, default)` 编码时，值等于默认就不写这个字段：`Unbreakable(true)` → `{}`，`Unbreakable(false)` → `{show_in_tooltip:0b}`。判断组件补丁的形状时别假设「有值就一定有字段」，空 compound 也可能是有意义的组件（见 C11）。日志 SBN-003a 执行记录、e06。

### K7 · 修 bug 的测试要做变异复核

新断言首跑即过不能证明它覆盖了 bug。验收（或执行方自查）时把修复临时关掉再跑一遍，确认新断言转红，再还原源码、删 `run/`。SBN-003a 验收里关掉开关型组件例外后 t01 / t03 失败，证明有效。日志 e06。

### K8 · 造 1.20.1 旧物品坐标别用 1.21 的 NbtUtils.writeBlockPos

1.21 的 `NbtUtils.writeBlockPos` 写出 int 数组，不是 1.20.1 的形状。测试里造旧物品 NBT 要手写：`captureMin` / `captureMax` / `rangeP1` / `rangeP2` 是大写 `{X,Y,Z}` compound，物品自己写的 `lockedPos` / `point1` / `point2` 是小写 `{x,y,z}`。日志 SBN-004 执行记录、e07。

### K9 · 组件 codec 里的映射函数抛异常会穿透整栈解析

`Codec.xmap` / `StreamCodec.map` 里的函数抛出的异常不会变成 DataResult 错误，`ItemStack.parse` 直接抛出（不是返回空 Optional）。按下标 / 名字取枚举的 codec 必须自带越界兜底（例：`SpatialBlueprintComponents.captureModeOf` 越界回 SAFE）；越界值可经 /give、损坏存档、客户端构造的创造栏包到达。日志 e07。

### K10 · 注释里的 SB-TODO 示例会污染桩数

桩数口径是 `grep -rn "SB-TODO(" src` 的实数。类注释 / 文档注释里举例写「SB-TODO(P5)」也会被算进去 —— 示例文本一律用全角括号（`SB-TODO（P5）`）。日志 SBN-005 执行记录、e08。

### K11 · GameTest 服的 OP 等级是 0

GameTest 服 `op-permission-level = 0`：`PlayerList.op(profile)` 写出的条目是 0 级，`hasPermissions(2)` 仍为 false。测 OP 路径要直接加 `ServerOpListEntry(profile, 4, false)`，finally 删掉。日志 SBN-006 执行记录、e09。

### K12 · FakePlayer 不会被传送；makeMockServerPlayerInLevel 别用

`FakePlayerFactory` 的假玩家，其网络处理器的 teleport 是空实现，`teleportTo` 对它不移动 —— 验证「服务端真的移动了玩家」要用在场玩家。
`GameTestHelper.makeMockServerPlayerInLevel` 已标记待删（用了破 0 警告基线，K1），且其 `isCreative()` 恒 true；照它的构造用公开 API 自建
（`new ServerPlayer` + `new Connection(SERVERBOUND)` + `EmbeddedChannel` + `PlayerList.placeNewPlayer`），finally 里 `getPlayerList().remove`。日志 SBN-007 执行记录、e10。

### K13 · C2S 解码按客户端计数分配内存，必须先夹上限

C2S 的 decode 在服务端网络线程、早于任何权限判定执行。凡按客户端给的计数 / 长度分配（`new ArrayList<>(n)`、`new byte[n]`、`new HashMap<>(n)` 等）都要先夹上限：
常量上限，或「计数 ≤ `buf.readableBytes()`」（每个元素至少 1 字节），越界走 `S2C_OperationResult.checkedCount` 抛 DecoderException 整包拒收。
「照 1.20.1 原样搬」会把旧线的这类漏洞一起搬来（SBN-008：SubmitProjectChanges 一个 5 字节 VarInt 可让服务端尝试分配 20 亿元素）。S2C 同类写法只影响客户端，服务端可信。日志 e11。

### K14 · 1.21 自动拆包让 1.20.1「写了但到不了」的 C2S 上限变得可达

NeoForge 1.21 的 GenericPacketSplitter 会把超长 C2S 拆包再在服务端拼回；1.20.1 有原版 C2S 单包 32767 字节上限挡着，代码里写的大上限（如上传单包的 32 MiB）实际到不了。
搬 C2S decode 的上限时按 1.20.1 **实际生效**的上限算，不照抄常量（SBN-009 把单包上传恢复为 `SINGLE_PACKET_LIMIT` 30000）。
夹法模板：常量上限 / 声明值 ≤ 配置上限（在分配前判）/ `checkedCount`；解压类负载再由 `SafeNbtIo` 的 NbtAccounter（不可信 64 MiB）兜第二道。K13 的延伸。日志 e12。

### K15 · 本机 git 输出含中文时按字节落地，不走 PowerShell 文本管道

PowerShell 的 `| Out-File` / `>` 会把 git 输出按 GBK 解码再写回，中文变乱码、还可能写坏源码里的字符串字面量。含非 ASCII 的 git 输出（diff、show、log）一律按字节落地：
Python `subprocess.run(..., capture_output=True)` 取 bytes 后以二进制写文件。日志 SBN-010 执行记录、e13。

### K16 · runServer 冒烟：轮询重定向的 stdout，「正常退出」三条都要满足

`run/logs/latest.log` 是 GameTest 服写的，冒烟时看的是 runServer 重定向出来的 stdout；gradle stderr 里的 `^C` 提示不算错误。
「正常退出」= RCON 发 stop 后 java 进程消失 **且** gradle 任务报 BUILD SUCCESSFUL。日志 SBN-010 执行记录、e13。

### K17 · 1.20.1 → 1.21 物品修复器保留旧 tag，成功判据看 components

原版 ITEM_STACK 修复器把 1.20.1 物品 `{id, Count, tag}` 升级时，结果里 `components` 与旧 `tag` **并存**（部分转换，tag 不删）。
判断「升级成功」看有没有出 `components`（或 tag 被吃光），不能以「tag 还在」判失败；失败要靠显式 ok 位区分（修复器抛异常 / 结果不是 compound 时原样返回）。
写法见 `LegacyDataFixer.migrateMaterialKey`。日志 SBN-011 执行记录、e14。

### K18 · 修复器写的名字是展开形，1.21 存盘写裸形：材料键迁移要压平

修复器把 `display.Name` 转成 `minecraft:custom_name` 时写展开形 `'{"text":"X"}'`，1.21 自己存盘对无格式纯文本写裸形 `'"X"'`；语义相同但 NBT 逐字不同，材料键摘要不同 → 升级出的旧物与新造的同物异键（存入 / 消耗对不上）。
凡按 NBT 摘要算键（D8）的迁移，都要先把 custom_name / lore 里「仅含 text 字符串的单键对象」压成裸形（`LegacyDataFixer.collapsePlainText`）；放置用的 NBT 不必压（读进真实物品后会重新编码）。日志 SBN-011 执行记录、e14。

### K19 · 迁移旧数据别漏了改名：纯 ID 也要过修复器

1.20.1 → 1.21 有物品 / 方块改名（例：`minecraft:grass` → `minecraft:short_grass`）。迁移旧数据时「没有 tag 就原样」是错的：纯 ID 键、只存注册名的字段也要过修复器取新 id，
否则旧 id 在 1.21 查不到、按空气算。带 tag 的也要用修复结果的 id，不能沿用旧 id。SBN-011 任务书漏了这条，云端验收补（af1c9bd，t08）。日志 e14。

### K20 · 1.21.1 弃用 BlockState.rotate(Rotation) 与 hasChunkAt(BlockPos)，照搬破 0 警告

javac 只打一行「使用或覆盖了已过时的 API」，要临时 -Xlint:deprecation 定位（定位完复原 build.gradle）。
旋转换 `rotate(LevelAccessor, BlockPos, Rotation)`（NeoForge 扩展，默认落回原版 rotate，原版方块结果不变）；区块判断换 `hasChunk(x >> 4, z >> 4)`（与 hasChunkAt 等价：都不看 Y）。
搬 1.20.1 代码碰到 rotate / hasChunkAt 先看弃用标记。日志 SBN-012 执行记录、e15。

### K21 · GameTest 的 mock 玩家登录时还在配置相位，发 play 包会抛

`placeNewPlayer` 直调造的 mock 玩家（SBN007Tests.mockPlayerInLevel）触发 PlayerLoggedInEvent 时连接仍在配置相位，NeoForge 相位检查拒绝 play 包并抛
`UnsupportedOperationException`，会炸掉整条 firePlayerLoggedIn 链、级联污染别的测试（1.20.1 的 SimpleChannel 不抛）。
登录时发包只兜这一种异常并记 debug，**不要 catch (Exception)** 静默吞一切（SBN-012 云端收窄 894ec85）。日志 e15。

### K22 · 1.21.1 手动热加载配置：整份替换 + acceptConfig，只 putAll 恒回旧值

FML 4 的 ConfigTracker.INSTANCE 内部表与 ModConfig.setConfig 都是包内可见；公开入口是 `ModConfigs.getModConfigs(modid)`。
手动 doReload 顺序：CommentedFileConfig 读盘（不合法就 spec.correct，只改内存）→ `loaded.config()` clear + putAll（整份替换）→
`spec.acceptConfig(loadedConfig)`（重建值表，拿到盘上值的关键）→ `spec.afterReload()`（清 ConfigValue 缓存）。只 putAll + afterReload 读出来恒是旧值。
FML 自带 ConfigWatcher 改盘后也会异步重载，两者并存无害。写法见 `C2S_ReloadConfigMessage.doReload`。日志 SBN-013 执行记录、e16。

### K23 · GameTest 服没有玩家名缓存；performPrefixedCommand 没有返回值

`server.getProfileCache()` 为 null：GameProfileArgument 按名字解析的命令参数在测试服跑不到（按源码 catch 转 unknown_player），端到端留实机。
1.21.1 的 `Commands.performPrefixedCommand` 返回 void，测试要拿命令返回值用 `dispatcher.execute(String, source)`（requires 拒绝时抛 CommandSyntaxException）。日志 SBN-013 执行记录、e16。

### K24 · 本机 night-config 3.8.3 的 CommentedFileConfig set + save 不落盘

set 后内存是新值、save() 后重读文件仍是旧值，游戏内还抛 `Integer cannot be cast to [C`。测试里改配置文件用直接文本替换那一行；
生产 doReload 只读不写不受影响。日志 SBN-013 执行记录、e16。

### K25 · 存盘写成 ListTag 的表不用 HashMap

HashMap 扩容后不缩容，读回的副本容量小、遍历顺序不同 → save 写出的 ListTag 顺序不确定，save → load → save 不相等（数据不丢，但往返测试在共享存档里随测试数增多而偶发转红）。
凡按遍历顺序写 ListTag 的表（含内层表）用 LinkedHashMap 或先排序；只写成 CompoundTag 的无所谓（CompoundTag 比较与顺序无关）。
SBN-013 验收修 MaterialSpace（1390509，t09）；1.20.1 同写法登记为可选跟。日志 e16。

### K26 · BlueprintData.deserialize 很宽容：越界 saveMode 曾是唯一抛出入口

SBN-014 实测：内联 blueprintData 里 saveMode 越界（如 99）→ `CaptureMode.fromOrdinal` 抛越界 → `readInlineData` 的 catch 记 WARN 返回 null。
e18 起 saveMode 读取改 `CaptureMode.fromOrdinalOrSafe`（越界回退 SAFE），deserialize 已无已知抛出入口：空 BlockStates 跳过、坏方块读成空气、空 Regions 返回空蓝图。
写「坏数据」测试别再假设 deserialize 会抛；断言「不抛、只读、没有方块」。日志 SBN-014 执行记录、e17、e18。

### K27 · fakePlayerSink 只接 FakePlayer；验 K21 逐步兜底要双证据

`BlueprintNetwork.fakePlayerSink` 只截 FakePlayer 的发包；配置相位的 mock 玩家（SBN007Tests.mockPlayerInLevel）发包必抛 UnsupportedOperationException。
验「每个发包点各自兜底」要同时拿到「每步一行 debug（sync skipped …）」与「orphanBagsDetected 文件日志」两份证据 —— 一个大 try 会把文件日志也吞掉。日志 SBN-014 执行记录、e17。

### K28 · MaterialSpace 没有公开 API 造「total = 0 的空袋」

bagDeposit 对 amount ≤ 0 直接 return，bagDepositAll 空清单直接 return；测试要这种状态只能反射往私有 bags 字段注入空内层表（finally 移除）。日志 SBN-014 执行记录、e17。

### C1 · 列表配置启动时的 correction WARN 是既有行为，别当 bug 修

启动日志里 `Incorrect key … was corrected … to its default` 这类 WARN 来自 `define(String, List)` 列表项的校验，与 Forge 1.20.1 源码逐字一致；文件没被手改时值不变。要根治得改 `defineListAllowEmpty` 并改字段类型（行为变更，待拍板）。日志 SBN-001 执行记录、e03。

### C2 · GameTest 日志只有批次级结果，逐条证据数注解

`runGameTestServer` 只打印 `Running test batch … (N tests)`、`[++++]`、`All N required tests passed`，不逐条列用例名。要逐条对照就 grep 测试类里 `@GameTest` 注解的实数（别把 import 行算进去），与 N 一致即全部通过。日志 SBN-001 执行记录、e03。

### C3 · 安全检测要覆盖解码器接受的全部形状，不只真实序列化出来的那种

1.21 成书 `components."minecraft:written_book_content".pages` 正常存成 `[{raw:"<JSON>", filtered?:…}]`，但 `Filterable` 解码器（`withAlternative`）也收裸字符串列表。检测按元素类型过滤（`getList(…, 10)`）就会整类漏掉 → 所有 pages / 文本列表都不按元素类型过滤地遍历（`BlueprintSanitizer.collectPageJsons`）。测试模板见 SBN002Tests s04c：先 `ItemStack.parse` 证明攻击形状可达，再断言被拦。日志 e04。

### C4 · 告示牌过滤文本 filtered_messages

`front_text` / `back_text` 下除 `messages` 外还有 `filtered_messages`（JSON 字符串列表，真实序列化总会写出）。开了文本过滤的玩家点告示牌时执行的是过滤版的点击事件，检测与净化必须与 `messages` 同口径。1.20.1 线同样缺，已登记待跟。日志 e04。

### C5 · 方块实体的隐式组件只在物品放置路径生效

`loadWithComponents` / `loadStatic` 只把 NBT 里的 `components` 读进缓存，不调 `applyImplicitComponents`；`container_loot` 等隐式组件只在 `applyComponentsFromItemStack`（BlockItem 放置）时生效（BlockEntity.java:294-318）。P4 写放置逻辑、写可达性测试时按这条来。日志 SBN-002a 报告四.1、e04。

### C6 · 1.21 方块实体 NBT 的 components 子标签是夹带路径

1.21 方块实体 NBT 可带 `components`，里面能塞 `minecraft:container`（潜影盒内容）、`minecraft:container_loot`（战利品表）。净化器已整条删除（s02b、s10）；新增净化规则时别漏掉这一层。日志 e04。

### C7 · 测试里 SignBlockEntity.setText 要先有 level

告示牌方块实体没进世界（level 为 null）就调 `setText` 会 NPE；GameTest 里先 `setLevel` 或先放进世界再调。日志 SBN-002 执行记录。

### C8 · D8 材料键的编码：与 ItemStack.save 的 components 同一个 Codec

`MaterialKey.of(ItemStack, Provider)` 用 `DataComponentPatch.CODEC` + `provider.createSerializationContext(NbtOps.INSTANCE)` 编码组件补丁，与 `ItemStack.save` 写出的 `components` 子标签同编码（`ItemStack.CODEC` 里就是这个 Codec 的 `optionalFieldOf`），所以实体身上的物品与手里的物品算出同一个键（SBN003Tests t02）。补丁里 `!` 前缀的键 = 「移除了某默认组件」（值为空 compound），是真差异，`pruneNoOps` 必须跳过不剔。日志 SBN-003 执行记录、e06。

### C10 · 1.21 空潜影盒挖起来不带任何组件

### C11 · 开关型组件编码为空 compound，材料键规范化必须保留

`minecraft:unbreakable`（默认显示提示时）、`minecraft:hide_tooltip`、`hide_additional_tooltip`、`creative_slot_lock`、`intangible_projectile`、`fire_resistant` 等「存在即生效」的组件编码出来是 `{}`（K6）。`MaterialKey.pruneNoOps` 只在补丁**顶层**、键名含 `:`、值**处理前**就为空 compound 时保留；处理后才变空的（如 `block_entity_data` 剔 id）与旧格式键（`display:{}`）照旧剔除。剔掉会让不可破坏镐与普通镐同键。1.20.1 的 `Unbreakable:1b` 是字节，旧线无此问题。日志 SBN-003a 执行记录、e06。

### C12 · 1.21 物品自定义数据：一键一组件，全部 persistent + networkSynchronized

### C14 · 1.21 网络改写口径（1.20.1 消息 → payload）
