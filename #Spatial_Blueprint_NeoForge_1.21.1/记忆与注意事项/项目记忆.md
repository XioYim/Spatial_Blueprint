## 读取顺序

1. **`#Spatial_Blueprint_NeoForge_1.21.1\待办事项.html`** —— 用户维护的待办清单（等拍板项 + 协议版本），AI 只读、只提议。主会话开头由 hook 注入；辅助 AI 与新会话自己读。**当前环境（构建标识 / 配置 / git / 备份表）在本文件末尾「环境现状」「备份记录」两节**，开工前必看。
2. **`记忆与注意事项\注意事项_目录.md`** —— 记忆总索引，先读它再决定读哪一段（怎么用见下一节）。
3. **`记忆与注意事项\注意事项_分类.md`** —— 记忆正文，按条目类型分三类，顺序固定为 **铁律 → 坑 → 参考**。改代码前**整读「铁律」段**；跑脚本 / 杀进程 / 换配置 / 派任务前先看 **K1 报警行**，再按需看其余 K 段；任务涉及某子系统时按目录里「读的时机」只读对应的 **C 段**。
4. 集成对象的机制取证：`记忆与注意事项\<外部mod>研究报告.html`（按需，一个外部集成对象一份，单文件 HTML；`html2text.ps1 -List` / `-Card` 只读一章；改相关代码前读）。

## 注意事项_目录.md —— 是什么、怎么用

- **路径**：`D:\Mods\Spatial_Blueprint_NeoForge_1.21.1\#Spatial_Blueprint_NeoForge_1.21.1\记忆与注意事项\注意事项_目录.md`
- **是什么**：`注意事项_分类.md` 的索引表。三张表（铁律 / 坑 / 参考），每行给出 **编号**（`T` 铁律 / `K` 坑 / `C` 参考）、**事项**、**在分类.md 的行号**、**读的时机**。
- **怎么用**：先在目录里按「读的时机」或关键字找到编号，再到 `注意事项_分类.md` 用行号定位那一段读（`Read` 带 offset）。**不要整读 `注意事项_分类.md`**，除了改代码前的铁律段。
- **行号只对应生成时的版本**：目录头部写着生成时间；谁改了 `注意事项_分类.md`（增删条目、段落变长）就要重新生成目录，否则行号漂移。改动前先看目录的生成时间是否晚于分类文件的最后修改时间。
- **写入**：两份都只有主会话能写，且**写前先问**——遇到值得记的坑 / 关键点，先在对话里说「想记到 T/K/C 哪段、一句话是什么」，用户点头再写；一条记忆 = 一句话要点 + 指向开发日志编号，机制 / 取证 / 改动经过写 `开发日志.md`。新增 = 在 `注意事项_分类.md` 对应类别的末尾加 `### T/K/C<N> · 标题`（N 取该类当前最大 +1），再重新生成 / 手改目录里的行。辅助 AI 发现该记的东西写在报告「建议记入踩坑记录」段，由主会话合并。

## 格式规矩

- 记忆类文档与开发日志 **Markdown（`.md`、UTF-8 无 BOM）**、测试清单纯文本（`.txt`），直接读；待办事项与研究报告是 **HTML**（**读走 `D:\Mods\项目工具\html2text.ps1`**）。写则直接编辑、不经转换器。整份覆盖写用 Write；小改用 Edit 定位上下文做外科式插入。TASK 手册与报告用 `.txt`（中文）。
- **追加**（开发日志加一节、测试清单加用例、分类文件加一条）：先读文件里最近一条照格式写，直接在文末追加；**禁止重写已有内容**、禁止引入别的格式。
- 时间一律 `YYYY-MM-DD HH:mm:ss`，精确到秒。
- 记忆目录 `C:\Users\Yim\.claude\projects\D--Mods-Spatial-Blueprint-NeoForge-1.21.1\memory\` **只有 `MEMORY.md` 一个文件、只写路径**，不再写独立记忆文件 —— 所有记忆都在 `记忆与注意事项\`，主辅 AI 共用。

## 派任务给辅助 AI

TASK 手册（`任务派发与核验\<任务号>_任务_<简述>.txt`）第一段必须有：

1. 备份：`D:\Mods\项目工具\备份.ps1 -Project D:\Mods\Spatial_Blueprint_NeoForge_1.21.1 -Note "<任务号> 执行前"`（安全手册 `D:\Mods\项目工具\安全手册.MD`）。
2. 接入：读 `D:\Mods\Spatial_Blueprint_NeoForge_1.21.1\#Spatial_Blueprint_NeoForge_1.21.1\记忆与注意事项\项目记忆.md`（本文件），按读取顺序走；涉及某子系统就指明 `注意事项_目录.md` 里的编号（如「读 C2 与 C5」），别让它整读分类文件。
3. 允许修改的文件清单（按设计需要哪些文件推，不按脑内清单列；范围别用目录名）。
4. 验收标准 + 报告模板。报告禁止代码块，只给「主张 + file:line」。

辅助 AI **可写**：自己的报告、`开发日志.md` 文末追加一节（`## <任务号> 执行记录`，编号用任务号，不占主序列编号）、`测试清单.txt`（TASK 指定范围，直接编辑、照现有格式写）。 **禁碰**：`待办事项.html`、`记忆与注意事项\` 下除本条允许之外的一切、记忆目录。踩到的坑写进报告「建议记入踩坑记录」段。 编号（日志 / 测试号）会被并行会话抢，用时取当前最大号 +1，别预留。
