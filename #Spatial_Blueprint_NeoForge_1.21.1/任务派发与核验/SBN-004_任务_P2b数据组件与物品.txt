========================================================
一、背景与目标
========================================================

P2 的后半段。本任务把「物品 NBT」换成自定义数据组件，并把物品、渲染方块、创造物品栏接上：

  组件：新建 item/SpatialBlueprintComponents（39 个组件类型，一键一组件，第三.1 节表）
  物品：13 个文件（11 个物品类 + AbstractBlueprintItem + SpatialBlueprintItems；注册 10 个物品，ProjectBlueprintItem 只是两个项目蓝图的父类，见第二节）
  方块：SpatialBlueprintRegistry、block/RenderBlock、block/entity/RenderBlockEntity
  迁移：新建 item/LegacyItemMigration —— 1.20.1 物品经原版 DataFixer 升级后落在 minecraft:custom_data 里的旧键，搬进本 mod 组件
  辅助：util/ItemSyncUtil、util/OrphanBlueprintGuard（物品已用到、只依赖原版；网络发送那一句打桩）
  主类：注册三组 DeferredRegister + 创造物品栏

本任务结束时：10 个物品与渲染方块在游戏里存在、能进创造物品栏、组件能存盘能同步、1.20.1 旧物品载入即迁移；
右键打开的界面、网络包、客户端缓存、渲染器仍然没有（打桩，P3～P6）。

三、已定方案
========================================================

总原则：逻辑、判断顺序、注释、翻译键、public static 访问器的**方法名与签名**一律不改（P3～P6 的调用方照原样接）；
只改「NBT 读写 → 组件读写」、API 签名、下面点名处。每个文件 diff -w 残差逐条进报告「改了写法的调用」。

1. 组件：item/SpatialBlueprintComponents
   a. DeferredRegister.createDataComponents(Registries.DATA_COMPONENT_TYPE, MODID)（J21）；
      每个类型 registerComponentType(id, b -> b.persistent(CODEC).networkSynchronized(STREAM_CODEC))，
      **全部都要 persistent + networkSynchronized** —— 1.20.1 的物品 NBT 本来就整份同步给客户端，界面要读 blueprint_id 等；少一个就是客户端看不见（双端不同步）。
      公开字段 public static final DeferredHolder<DataComponentType<?>, DataComponentType<T>> 大写蛇形名（如 BLUEPRINT_ID）；
      static register(IEventBus)。不写 cacheEncoding。
   b. 一键一组件，组件 ID = 旧 NBT 键的 snake_case（下表）。值类型全部不可变：String、Integer、Long、Double、Boolean、BlockPos、Rotation、CaptureMode。
      **BlockPos 在 setter 里一律 pos.immutable() 再 set**（调用方可能传 MutableBlockPos，存进组件后被改就是静默串值）。
      理由（写进类注释）：每个 setter 是一次原子 set，没有「取出副本改完忘写回」这类坑（迁移计划书第四节）；旧键迁移是一张对照表。
   c. Codec / StreamCodec（J22）：
      String  → Codec.STRING / ByteBufCodecs.STRING_UTF8
      Integer → Codec.INT / ByteBufCodecs.VAR_INT        Long → Codec.LONG / ByteBufCodecs.VAR_LONG
      Double  → Codec.DOUBLE / ByteBufCodecs.DOUBLE      Boolean → Codec.BOOL / ByteBufCodecs.BOOL
      BlockPos → BlockPos.CODEC / BlockPos.STREAM_CODEC
      Rotation → Rotation.CODEC / NeoForgeStreamCodecs.enumCodec(Rotation.class)（Rotation 没有 STREAM_CODEC，J22）
      CaptureMode → Codec.INT.xmap(CaptureMode::fromOrdinal, Enum::ordinal) / ByteBufCodecs.VAR_INT.map(同上)
                    —— 与 1.20.1 物品 NBT、蓝图文件里的 saveMode 同一个口径（ordinal）；fromOrdinal 越界回 SAFE 已有。

   对照表（NBT 键 1.20.1 → 组件 ID spatial_blueprint:… · 值类型 · 旧值读法（三.3 用））：
     blueprintId     → blueprint_id      String
     blueprintName   → blueprint_name    String
     saveMode        → save_mode         CaptureMode   int → CaptureMode.fromOrdinal
     animDuration    → anim_duration     Integer
     creatorName     → creator_name      String
     rotation        → rotation          Rotation      字符串 = Rotation.name()（大写，如 CLOCKWISE_90）→ Rotation.valueOf，非法跳过
     xOffset / yOffset / zOffset → x_offset / y_offset / z_offset   Integer
     alignMode       → align_mode        String
     locked          → locked            Boolean       byte
     lockedPos       → locked_pos        BlockPos      compound {x,y,z}（小写，SpatialBlueprintItem 自己写的）
     clearFirst      → clear_first       Boolean
     point1 / point2 → point1 / point2   BlockPos      compound {x,y,z}（小写，BlankBlueprintItem 自己写的）
     completionTime  → completion_time   Long
     sourceType      → source_type       String
     captureMin / captureMax → capture_min / capture_max   BlockPos   1.20.1 NbtUtils.writeBlockPos = {X,Y,Z}（大写）→ NbtCompat.readBlockPos
     tpX / tpY / tpZ → tp_x / tp_y / tp_z   Double
     tpDimension     → tp_dimension      String
     worldUuid / worldName → world_uuid / world_name   String
     engProjectId / engProjectName / engDimension → eng_project_id / eng_project_name / eng_dimension   String
     engStartX/Y/Z   → eng_start         BlockPos      三个 int 合成一个（三个键都在才迁；缺任一 → 按 0 补，与 1.20.1 getInt 缺键 = 0 一致）
     engEndX/Y/Z     → eng_end           BlockPos      同上
     sbTaskSetId     → sb_task_set_id    String
     sbEntryIndex    → sb_entry_index    Integer
     projectId / taskSetId / projectName / projectStage / projectDim
                     → project_id / task_set_id / project_name / project_stage / project_dim   String
     rangeP1 / rangeP2 → range_p1 / range_p2   BlockPos   {X,Y,Z}（NbtUtils.writeBlockPos）→ NbtCompat.readBlockPos
   共 39 个。另两个旧键不做组件：forceCancelled（全仓库只有 BuildBlueprintItem 一处 remove、没有写入方 → 废键，迁移时删掉）、
   blueprintData（内联蓝图数据，见三.3.e）。

3. 旧物品迁移：item/LegacyItemMigration
   a. 路径：1.20.1 存档 / 蓝图文件里的物品先经原版 DataFixer（ItemStackComponentizationFix）升级，本 mod 的自定义键不认识、
      整体落进 minecraft:custom_data。原版在 ItemStack 构造（磁盘解码、网络解码）与 applyComponents 时调用
      Item#verifyComponentsAfterLoad（J26：两处构造器 + 两个 applyComponents；PlayerHeadItem 就是在这里改组件的先例）。
      → 在这里把 custom_data 里的旧键按三.1 对照表搬进组件，搬过的键从 custom_data 删掉；删完为空就 remove(CUSTOM_DATA)。
   b. 双端：迁移是纯函数（同输入同输出），服务端与客户端各自解码时算出同一结果，不引入不同步；不发包、不读文件、不读配置。
   c. 幂等：没有 custom_data、或 custom_data 里没有对照表里的键 → 直接返回，不改 stack（热路径，每次构造都会调）。
      已经有同名组件时（理论上不该发生）：组件为准，旧键照样删掉。
   d. 只迁对照表里的键 + 删 forceCancelled；类型不对的旧值（例：rotation 不是合法名字）跳过不迁、旧键照样删掉，不抛异常、不刷日志。
      custom_data 里其它键（别的 mod / 数据包写的）原样保留。
   e. blueprintData（内联蓝图数据）**不动**，留在 custom_data：它是整份方块数据，D1 要求物品只存引用，转存成蓝图文件要先过 DataFixer（P4）。
      这是唯一允许留在 custom_data 里的本 mod 旧键；类注释写明。
   f. public static void migrate(ItemStack stack)；另给测试用 public static boolean needsMigration(CustomData data) 可选。
