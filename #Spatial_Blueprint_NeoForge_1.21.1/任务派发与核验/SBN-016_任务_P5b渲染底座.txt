========================================================
一、背景与目标
========================================================

P5 第二段。SBN-015 已建好客户端入口与缓存；渲染没有。本任务搬「渲染底座」—— 不含选区渲染器 BlueprintSelectionRenderer（2520 行，SBN-017）：
  client/outliner/（6 个，约 1040 行）：Outline、AABBOutline、ChasingAABBOutline、CornerOutline、Outliner、SBOutlinerRenderTypes
      —— Create 风格的线框 / 半透明面 / 角标渲染；由 BlueprintSelectionRenderer 驱动（tick + 渲染），SBN-017 接。
  client/renderer/RenderBlockRenderer（72 行）：渲染方块（放置动画里那个逐步长大 / 收缩的方块）的 BlockEntityRenderer。
  client/BlueprintFakeWorld（85 行）：幽灵预览用的最小 BlockAndTintGetter（满亮度、相对坐标），SBN-017 的预览 VBO 用。
  block/RenderBlock 的破坏特效：1.20.1 的 addDestroyEffects 在方块类里（引用 ParticleEngine，客户端类）；1.21 改走 IClientBlockExtensions，
      目前是 SB-TODO(P5) 桩（RenderBlock.onRemove 里注释掉的缓存）。
要清的 2 条桩：SpatialBlueprintClient 的「注册 RenderBlockRenderer」、RenderBlock 的破坏特效。

1.21 渲染 API 变化（云端已 javap，第四节）：顶点链式调用整体改名（vertex/color/uv/overlayCoords/uv2/normal/endVertex → addVertex/setColor/setUv/setOverlay/setLight/setNormal，无 endVertex）；
ResourceLocation 构造器私有；ModelData 换 NeoForge 包；BlockEntityRenderer 用 EntityRenderersEvent.RegisterRenderers 注册；
方块破坏粒子走 RegisterClientExtensionsEvent。RenderLevelStageEvent 的 pose stack / 相机平移约定在 1.21 可能与 1.20.1 不同（Outline 内部按 -camera 平移），**这是手测的重点**。

三、已定方案
========================================================

总原则：几何、颜色、透明度、淡出时长、批次顺序等渲染逻辑一律不改，只换 API；每个文件 diff -w 残差逐条进报告。

1. 顶点 API（outliner 5 个文件）
   a. 1.20.1「consumer.vertex(x,y,z).color(...).uv(u,v).overlayCoords(o).uv2(l).normal(nx,ny,nz).endVertex()」→
      consumer.addVertex(x,y,z).setColor(...).setUv(u,v).setOverlay(o).setLight(l).setNormal(nx,ny,nz)（J49，无 endVertex，字段顺序不变，NEW_ENTITY 格式六项必须齐）。
      color 的参数是 int 还是 float 照 1.20.1 实际类型选对应重载（J49 两种都有）。
   b. pose.normal() 仍是 Matrix3f（J49）；如需改用 PoseStack.Pose 版的 addVertex / setNormal 重载，只在实测有必要时并写进报告。
   c. SBOutlinerRenderTypes：RenderType.create 的七参数重载、RenderStateShard 的各常量（RENDERTYPE_ENTITY_SOLID_SHADER 等）在 1.21.1 仍在（J49）；
      new ResourceLocation("textures/misc/white.png") → ResourceLocation.withDefaultNamespace(...)（J49）；其余 CompositeState 建造链原样。
2. RenderBlockRenderer
   a. ModelData 换 net.neoforged.neoforge.client.model.data.ModelData；modelRenderer.tesselateBlock 的十二参数重载在 1.21.1 仍在（J49）；renderSingleBlock 重载照实测。
   b. render(...) 方法签名与 RenderBlockEntity 的字段读取（drawSize / nextDrawSize / getMaxSize / renderBlock）原样。
   c. 注册：SpatialBlueprintClient 里给 modEventBus 加 EntityRenderersEvent.RegisterRenderers 监听，event.registerBlockEntityRenderer(SpatialBlueprintRegistry.RENDER_BLOCK_ENTITY.get(), RenderBlockRenderer::new)（J49）；去掉那条 SB-TODO(P5)。
3. BlueprintFakeWorld：@OnlyIn 去掉；实现的 BlockAndTintGetter 方法（1.21.1 里 getBrightness / getRawBrightness 已是 default，getShade / getLightEngine / getBlockTint 仍抽象）照 javap 补齐或保留 @Override；
   逻辑（满亮度 15、getShade 五档系数、getBlockTint 用 origin 偏移取真实世界色）原样。
4. 破坏特效
   a. client/RenderBlockParticleCache：纯逻辑（不引用 net.minecraft.client，GameTest 可测）：put(pos, state) / remove(pos) → state 或 null / clear()。1.20.1 的静态 HashMap 从未清过 → 现在纳入断线清缓存（SpatialBlueprintClient.clearAllCaches 第 13 个），报告注明这是有意增加。
   b. block/RenderBlock.onRemove：把桩注释换成 RenderBlockParticleCache.put(pos.immutable(), rbe.targetBlock)（判断条件原样：仅客户端、移除为空气、targetBlock 非空气）。
      这一处对 client 包的引用只在 level.isClientSide() 分支里执行（K29），报告列入「公共包对 client 包的引用」清单。
   c. client/RenderBlockClientExtensions implements IClientBlockExtensions：addDestroyEffects(state, level, pos, engine)：cache.remove(pos)，非空且非空气 → engine.destroy(pos, target)；**无论有无缓存都 return true**（抑制黑紫缺失纹理的默认粒子，1.20.1 原语义）。
      在 SpatialBlueprintClient 里给 modEventBus 加 RegisterClientExtensionsEvent 监听：event.registerBlock(new RenderBlockClientExtensions(), SpatialBlueprintRegistry 里 RenderBlock 的 DeferredBlock.get())（J49；取块的写法照 SpatialBlueprintRegistry 实际字段）。
   d. 去掉 RenderBlock 里那条 SB-TODO(P5) 桩注释。
5. 调试驱动 client/outliner/OutlinerDebug（云端补：outliner 在 SBN-017 之前没有驱动者，没有它 016 的手测看不到任何 outliner 画面）
   a. 仅当环境变量 SB_DEBUG_OUTLINER 非空时，由 SpatialBlueprintClient 注册（modEventBus 之外的游戏总线：ClientTickEvent.Post → Outliner.tickOutlines + 每 tick 刷新下面四个对象；
      RenderLevelStageEvent（Stage.AFTER_PARTICLES）→ 与 1.20.1 BlueprintSelectionRenderer.renderOutlines 同写法：pushPose、取 mc.renderBuffers().bufferSource()、
      Outliner.getInstance().renderOutlines(ps, bufSrc, camera, partialTick)、popPose、endBatch；partialTick 取 event.getPartialTick().getGameTimeDeltaPartialTick(false)，J49）。
   b. 以玩家脚下方块位置 P 为基准，每 tick 刷新（slot 名固定 dbg_*，Outliner.keep/showXxx 的用法照 1.20.1）：
        A 常规深度框：P+(3,0,0) 的单格 AABB（showAABB，默认深度测试，应被墙挡住）
        B 无深度框：P+(-3,0,0) 的单格 AABB（.disableDepth 之类的参数照 OutlineParams 实际 API，隔墙可见）
        C 追随框：chaseAABB，跟随准星指向的方块（mc.hitResult 是 BLOCK 时）；没指向方块时不刷新（让它自然淡出，检验淡出）
        D 角标：showCorner 在 P+(0,0,3) 处，长度 0.5、三个方向标记
   c. 环境变量未设置时本类不注册、不产生任何行为（默认构建零影响）；类头注释写明用途与开关。SBN-017 接入 BlueprintSelectionRenderer 后，主会话决定删除或保留。
