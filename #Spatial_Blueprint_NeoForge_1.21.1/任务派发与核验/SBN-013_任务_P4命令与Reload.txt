========================================================

总原则同 SBN-005～012：字段、校验、权限等级、翻译键、日志文本、判断顺序一律不改；按 BlueprintNetwork 类注释（C14）改写。

1. BlueprintNetwork：register 里追加 C2S_ReloadConfigMessage 一条，playToServer（1.20.1 是 c2s）；payload ID 按命名规则（类名 snake_case）。
   空消息 codec 按 C15：ofMember + 空 encode / decode，不用 StreamCodec.unit。其余零改动。

2. C2S_ReloadConfigMessage
   a. handle(IPayloadContext) + handleServer(msg, ServerPlayer)；handleServer 里「player 为 null 或 !hasPermissions(2) → return」原样，成功后 sendSystemMessage 原样。
   b. doReload 必须改写（1.20.1 用的 ConfigTracker.INSTANCE.configSets() 在 FML 4 是包内可见字段，ForgeConfigSpec → ModConfigSpec）。
      口径：三步语义不变 ——「磁盘重读 → 清 ConfigValue 缓存 → 清本 mod 派生缓存」：
        for (ModConfig mc : ModConfigs.getModConfigs(SpatialBlueprintMod.MODID)) {
          loaded = mc.getLoadedConfig()；为 null 跳过；
          CommentedFileConfig.of(mc.getFullPath()) → load() → 若 !mc.getSpec().isCorrect(fc) 则 mc.getSpec().correct(fc)（只改内存，不回写磁盘）→
          loaded.config().putAll(fc) → 关闭 fc；
          mc.getSpec() instanceof ModConfigSpec spec → spec.afterReload()；
        }
        外层 try / catch 与 WARN 文本原样；最后 BlueprintConfig.clearCache()、GeneratedSubstitutionsConfig.invalidateCache() 原样。
      （本段是云端给的写法骨架，不是代码块照抄；实测某步 API 不同就照实测，写进「任务书出入」。）
   c. 背景（写进报告第七节）：FML 4 自带 ConfigWatcher，改盘后会异步自动重载并发 ModConfigEvent.Reloading（主类已挂 BlueprintConfig::onConfigReload）；
      手动 doReload 的价值是「立即生效 + GUI 用 .set() 改内存值后恢复成盘上值」。两者并存重复清缓存无害。

3. SBCommands
   a. 注册：RegisterCommandsEvent 换 net.neoforged.neoforge.event.RegisterCommandsEvent（J46），主类 addListener 一行（第二节）。
   b. 命令树、requires(hasPermission(2)) 的挂载位置、参数（IntegerArgumentType、GameProfileArgument）逐字原样 —— 验收按 requires 计数与挂载节点比对。
   c. 网络：syncTeleportPerm、executeOpenConfig 的 CHANNEL.send → BlueprintNetwork.sendToPlayer；其余零改动。
   d. 物品数据：若 project claim / activate 里有 stack.getTag() 直读，按 C12 走访问器（null 补 ""，与 SBN-010 同）；没有就报告写「无」。
   e. executeUndo：isCreative → 冷却 → pop → 维度 → restoreUndo → 撤回后冷却 → 声音 / 消息，顺序原样。
