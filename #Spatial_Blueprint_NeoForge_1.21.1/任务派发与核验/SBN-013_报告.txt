六、任务书出入（3 处，均照实测做 / 如实报告）
1. 三.2.b 给的 doReload 骨架在 1.21.1 上不足以生效：J46 明确 ConfigTracker.INSTANCE 包内可见，FML 4 的正规 reload 走
   ConfigTracker 内部 `modConfig.setConfig(new LoadedConfig(...), Reloading)`（包内）。骨架的「putAll + afterReload」组合实测
   `.get()` 恒回旧值（t03 首轮红）。按 FML setConfig 的语义手动补全：REPLACE 重建（clear+putAll）+ `spec.acceptConfig(loadedConfig)`
   （重建 spec 值表，这是拿到盘上值的关键）+ afterReload（清 ConfigValue 缓存）。t03 三条断言全绿；另以注释说明「为什么必须 acceptConfig」。
2. GameTest 服 `server.getProfileCache()` 为 null（离线测试服未初始化用户缓存）：命令的 GameProfileArgument 名字参数路径
   （grant/revoke/space <player> 的解析）在此环境不可达（NPE 被 SBCommands 的 catch 转为 unknown_player）。测试如实拆分：
   t06 以「权限表 API + syncTeleportPerm 包断言 + list 命令（null-safe 路径）+ 离线 UUID 授权」覆盖；
   t07 以「space 自查 + config」覆盖，space <player> 的 requires 挂载在 t04 覆盖。名字参数的真实端到端留 P6/P7 实机。
3. 本机 night-config 3.8.3 的 CommentedFileConfig.set+save 不落盘：独立实验（core+toml jar 直接跑，与游戏同一 jar 版本）复现
   ——set 后内存新值、save() 后重读文件仍是旧值；游戏内该调用还抛 `Integer cannot be cast to [C`。t03 的「改盘」手段改为
   直接文本替换 maxVolumeSpatial 行（测试手段，不影响生产路径：doReload 只读不写）。第 1 条的「旧值恒回」与第 3 条的存疑
   save 行为已分别验证（前者由 acceptConfig 修复、后者只存在于测试手段）。

七、双端同步自查（Reload 后客户端拿到的配置是否同步；tpperm 改后在线玩家的同步；ConfigWatcher 与手动 doReload 并存）
1. 配置热加载是**服务端**行为（doReload 只改服务端内存配置与缓存）。客户端手里的配置镜像分两类：
   a) 登录时下发的 S2C_ConfigSyncMessage（7 个体积上限 + 槽位上限，fromConfig；由 BlueprintPlacementHandler.onPlayerLogin 推送）——
      **reload 后不主动重推**（与 1.20.1 行为一致；客户端重登时拿到新值）。
   b) 配置界面打开时下发的 S2C_ConfigValuesMessage / S2C_ConfigPermMessage —— 重开界面即拿新值（服务端权威，无客户端缓存滞留）。
2. tpperm 改动后在线玩家即时同步：executeTpPerm 对每个目标 `getPlayerList().getPlayer(id)` 查在线 → syncTeleportPerm（:388-390）；
   GameTest 环境无「在线玩家」条件（FakePlayer 不在列表、mock 玩家走真连接收不到 sink），该路径以直接调用 syncTeleportPerm 的包断言覆盖（六.2）。
3. ConfigWatcher 与手动 doReload 并存：FML 4 自带 ConfigWatcher 监听配置文件磁盘变化 → 内部 setConfig（acceptConfig + Reloading 事件
   → 主类 BlueprintConfig::onConfigReload 清缓存）；手动 doReload 是「立即生效 + 把 GUI 用 .set() 改的内存值恢复成盘上值」的补充。
   两者并存重复清缓存无害（t03 c 步骤即在该并存环境下断言成功）。
4. 命令结果反馈：sendSuccess/sendFailure 走 CommandSourceStack（玩家源即聊天栏），无额外客户端包；/sb space 与 /sb config 的
   客户端动作走既有 S2C（MaterialSpaceSync 全量+开界面、OpenConfig），本次零改动。
