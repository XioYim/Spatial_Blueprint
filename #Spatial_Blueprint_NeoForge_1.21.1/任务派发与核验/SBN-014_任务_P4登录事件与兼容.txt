三、已定方案
========================================================

总原则同前：判断顺序、翻译键、日志文本、权限等级一律不改。每个文件 diff -w 残差逐条进报告。

1. 主类事件
   a. 注册：NeoForge.EVENT_BUS.addListener(SpatialBlueprintMod::onPlayerLogout / onPlayerLogin / onChangeGameMode)，放在 SBCommands 那行之后（1.20.1 同顺序）；
      ServerStopping 那条已有，不动。事件类换 net.neoforged.neoforge.event.entity.player.PlayerEvent 同名内部类（J47）。
   b. onPlayerLogin：四步顺序原样（syncTeleportPerm → syncWorldIdentity → notifyLostDimensionalBlueprints → syncConfigPerm）。
      **K21**：GameTest 的 mock 玩家在配置相位触发登录事件，每一次发包都会抛 UnsupportedOperationException。
      每个发包点各自 try / catch (UnsupportedOperationException)，记 debug 后继续下一步（写一个 private 助手统一处理即可）；
      禁止 catch (Exception)，禁止整段一个 try（前一步抛了会把后面几步——包括 orphanBagsDetected 的文件日志——一起跳过）。
      SBCommands.syncTeleportPerm 本身不改（不在第二节清单）：在主类调用处兜。
   c. CHANNEL.send → BlueprintNetwork.sendToPlayer；sp.server.getWorldData().getLevelName() 原样（1.21 仍在，J47）。
   d. onChangeGameMode：「hasPermissions(2) || 新模式 == CREATIVE || TeleportPermissions.has」判定原样，必须用 event.getNewGameMode()（注释原样保留）。
   e. onPlayerLogout：服务端分支三步原样；else 分支（1.20.1 用 DistExecutor 清 ClientMaterialSpaceCache / ClientTeleportPermCache / ClientConfigPermCache）
      整段换成一条 SB-TODO(P5) 桩注释（写清三个缓存名与「不许用运行时 dist 判断代替类加载隔离」这条 1.20.1 注释的要点），不引用任何客户端类。

2. ForagersInsightCompat：原样搬，FMLPaths 换 net.neoforged.fml.loading.FMLPaths；正则、幂等分支、日志文本不改。
   主类调用位置同 1.20.1：registerConfig(BlueprintConfig) 之后、registerConfig(GeneratedSubstitutionsConfig) 之前。

3. AbstractBlueprintItem.getBlueprintDataServer（一.c 拍板）：
   id 非空 → BlueprintStorage.load(id)，非 null 直接返回；否则 → readInlineData(stack)：
   取 stack 的 DataComponents.CUSTOM_DATA（没有 → null）→ copyTag 里有 "blueprintData" 才读 → BlueprintData.deserialize(该子标签)，
   异常时 WARN（1.20.1 文本原样）返回 null。只读：不改 stack、不写文件、不发包。Javadoc「只认文件，D1」一句改成与新语义一致（写明 1.20.1 同语义与 D1 的关系）。
