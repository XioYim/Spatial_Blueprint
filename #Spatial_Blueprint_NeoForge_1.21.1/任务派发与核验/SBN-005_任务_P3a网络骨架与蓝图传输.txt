三、已定方案
========================================================

总原则：字段、校验、上限常量、翻译键、日志文本、判断顺序一律不改；只按三.2 的口径改写 API。每个文件 diff -w 残差逐条进报告。

1. BlueprintNetwork
   a. 注册：public static void register(RegisterPayloadHandlersEvent event)（mod 总线，J31）：
      PayloadRegistrar r = event.registrar(protocolVersion())（registrar 的参数就是版本号，J31；等价于 new PayloadRegistrar(版本)）——
      **效果必须是注册器版本 = mod 版本**（D4），报告写明实测依据。
      C2S 用 r.playToServer(TYPE, STREAM_CODEC, X::handle)，S2C 用 r.playToClient(...)；**方向必须绑定**（1.20.1 注释里的改包攻击，
      NeoForge 按注册方向校验，反向包直接断开）。不设 executesOn（默认 MAIN，J31），handler 里不再 enqueueWork。
      1.20.1 「注册顺序 = 线上序号，只能末尾追加」那段注释删掉，改写成一句：1.21 按 payload ID 区分，顺序无关；增删 payload / 改 wire format
      仍须 bump mod_version（D4）。
   b. D4：public static String protocolVersion() = ModList 取本 mod 容器的 getModInfo().getVersion().toString()，取不到回 "1.0.0"（与 1.20.1 同）。
      ModList 在 net.neoforged.fml（J31）。
   c. 发送封装（替换 1.20.1 全部 CHANNEL.send / sendToServer 写法）：
        public static void sendToPlayer(ServerPlayer player, CustomPacketPayload payload)
          —— player 是 FakePlayer（net.neoforged.neoforge.common.util.FakePlayer）时不走网络，交给
             public static volatile BiConsumer<ServerPlayer, CustomPacketPayload> fakePlayerSink（默认丢弃）；否则 PacketDistributor.sendToPlayer。
             理由（写进注释）：假玩家没有真连接，别的 mod 的假玩家触发我们的逻辑时丢弃是正确行为；GameTest 借这个口子收回包断言。
        public static void sendToServer(CustomPacketPayload payload) —— PacketDistributor.sendToServer。
      本任务及以后所有发包一律走这两个封装，不直接调 PacketDistributor。
   d. D5 sendBlueprintTo(ServerPlayer, String, BlueprintData)：逻辑原样（整份 writeCompressed → 按 CHUNK_SIZE 切 → 超 MAX_TOTAL_CHUNKS 记 warn 不发）。
      为了能测，切块部分抽成 public static List<S2C_BlueprintChunkMessage> splitIntoChunks(String blueprintId, byte[] full)
      （超上限返回 null，由调用方记原来那条 warn）；sendBlueprintTo 调它再逐个 sendToPlayer。行为不变。

2. 消息改写口径（本任务 8 个照做；SBN-006 / 007 沿用 —— 写进 BlueprintNetwork 类注释，简短）
   a. 类名、包名、字段、构造器不改。类加 implements CustomPacketPayload；
      public static final CustomPacketPayload.Type<X> TYPE = new CustomPacketPayload.Type<>(ResourceLocation.fromNamespaceAndPath(MODID, <id>))，
      <id> = 类名转小写 snake_case（S2C_OperationResult → s2c_operation_result，C2S_RequestBlueprintDataMessage → c2s_request_blueprint_data_message）；
      @Override public Type<X> type() { return TYPE; }。
   b. 编解码：1.20.1 的 static encode(X, FriendlyByteBuf) / static decode(FriendlyByteBuf) 原样保留，
      public static final StreamCodec<FriendlyByteBuf, X> STREAM_CODEC = StreamCodec.ofMember(X::encode, X::decode)（J32）。
      decode 里的 DecoderException 上限校验一个不删。需要注册表的字段（ItemStack、Component）才改用 RegistryFriendlyByteBuf —— 本任务 8 个都不需要。
      1.20.1 若用了 1.21 已删的 FriendlyByteBuf 方法，按 J32 换等价写法并进报告。
   c. C2S handler：public static void handle(X msg, IPayloadContext ctx) { if (ctx.player() instanceof ServerPlayer player) handleServer(msg, player); }
      + static void handleServer(X msg, ServerPlayer player)（public，测试直接调）装原来 enqueueWork 里的全部逻辑；
      去掉 enqueueWork、setPacketHandled、getSender() 判空（改成上面的 instanceof）。
   d. S2C handler：public static void handle(X msg, IPayloadContext ctx)。
      **payload 类里不许出现任何客户端类引用**（net.minecraft.client.*、本 mod 的 client / gui 包、NotifySound 的客户端方法）——
      1.20.1 靠 @OnlyIn 在专服上剥掉这些方法体（S2C_OperationResult 的注释写了不剥就崩）；NeoForge 1.21 不剥离，专服加载 payload 类时就会出事。
      客户端处理体整体换成一行 // SB-TODO(P5): <原来做什么>（P5 建 client 包里的客户端处理类，由它接）。
      例外：S2C_IllegalBlocksListMessage 的 handle 只是把字段写进本类的 static volatile 字段、不碰客户端类 —— 原样保留，不打桩。
   e. 发送点：CHANNEL.send(PacketDistributor.PLAYER.with(() -> p), m) → BlueprintNetwork.sendToPlayer(p, m)。

3. 各消息要点
   a. S2C_BlueprintChunkMessage：CHUNK_SIZE 512_000、MAX_TOTAL_CHUNKS 256 与三条 decode 校验原样；handle 打桩（ClientBlueprintCache.receiveChunk）。
   b. S2C_BlueprintDataMessage：MAX_PAYLOAD_BYTES、SafeNbtIo 解码原样；handle 打桩（ClientBlueprintCache.put）。
   c. S2C_BlueprintDataFailMessage：handle 打桩（ClientBlueprintCache.markFailed）。
   d. C2S_RequestBlueprintDataMessage：COOLDOWN_MS、LAST_REQUEST 限流、canManageBlueprint 判定、三种失败回包原样。
   e. C2S_DiscardInvalidBlueprintMessage：两只手遍历、服务端重验 placed、换空白蓝图 + ItemSyncUtil.syncHand 原样。
   f. S2C_OperationResult：三个构造器、success / failure 工厂、checkedCount（public，SBN-006 的 S2C 列表消息会用）、MAX_DETAIL_ARGS 原样；
      handleClient 整段打桩。
   g. S2C_OpenVoidScreenMessage：空消息；handle 打桩（打开 VoidDimensionalScreen）。编解码用 StreamCodec.unit(INSTANCE) 或 ofMember 均可，报告写明。
   h. S2C_IllegalBlocksListMessage：保留占位文件里的 7 个嵌套 record（签名不变），补回 1.20.1 的字段、构造器、encode / decode、
      client* 静态字段与 hasCrossingBoxEntityIn、handle（见 2.d 例外）；删掉文件头那条 SB-TODO(P3)。
   i. server/BlueprintValidator：原样搬；只改 1.21 API 残差（若有）。

4. 拆 SBN-004 的 P3 桩

   恢复 1.20.1 的发送语句，写法改成 BlueprintNetwork.sendToPlayer(sp, new …)。其余零改动。

   modEventBus.addListener(BlueprintNetwork::register)，删掉 SB-TODO(P3): BlueprintNetwork。其余 SB-TODO 不动。
