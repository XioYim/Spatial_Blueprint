原文：
{ "Name": "minecraft:grass" }

── 样本二：旧附魔剑物品（legacyA）──
原文：
{ "id": "minecraft:diamond_sword", "Count": 1b, "tag": { "Enchantments": [{ "id": "minecraft:sharpness", "lvl": 3s }], "display": { "Name": '{"text":"Test Blade"}' } } }

读取验证：ItemStack.parse 成功，与 1.21 真实 API 造的同款剑 isSameItemSameComponents 一致（t01）。

升级后：与样本二同一新键（RepairCost / minecraft:repair_cost 在规范化时忽略）。

升级后：同一新键（== MaterialKey.of(真实锋利 III 命名钻石剑, provider)，t04 断言逐字相等）数量 5；
minecraft:stone 数量 5 原样；keyTags 换成新 components（可组展示栈，与真实剑一致）。

── 形状取证（调试运行实测，非断言）──
修复器输出的 components 里 custom_name 为展开形 '{"text":"Test Blade"}'，
而 1.21 真实存盘为裸形 '"Test Blade"'（enchantments 两边逐字相同）。
语义相同但摘要不同 → 迁移时把纯文本 JSON 压成裸形（LegacyDataFixer.collapsePlainText，
custom_name / lore），否则新旧同物异键。见报告六.1。
