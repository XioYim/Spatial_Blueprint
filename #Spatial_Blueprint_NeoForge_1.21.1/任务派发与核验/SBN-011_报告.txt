六、任务书出入
1. 成功判据（有意差异）：初版以“旧 tag 残留即失败”判，实测修复器保留 tag 与 components 并存
   （部分转换），改判据为“无 components 且 tag 残留才是失败”（LegacyDataFixer.java:130-134）。
2. MigratedKey 多一个 ok 位（key, components, ok）：fix 失败（抛异常/非 compound）时 probe 原样返回，
   此时 components 缺失、make 会算出纯 ID 键——按 key 是否变化无法区分失败与“旧 tag 被吃光的成功”，
   故用显式 ok 位；失败时调用方保留原键与原 tag 并计数（与迁移前行为一致）。
3. 纯文本压平（有意差异，D8 一致性真问题）：修复器 custom_name 写展开形 '{"text":"X"}'，
   1.21 存盘写裸形 '"X"'（enchantments 逐字相同，调试 prettyPrint 实测），语义同但摘要异——
   不压则升级出的旧物与新造的同物异键（存入/消耗对不上）。迁移时把纯文本 JSON 压成裸形
   （custom_name / lore，collapsePlainText；仅单 text 键对象，失败原样保留）。
   测试用带名剑覆盖（比任务书 t04 要求的无名剑更强）；放置路径用的 NBT 不碰，只影响键计算。
4. 其余：BE/ENTITY 修复器会递归容器/展示框物品（t02 箱剑与框物品都正确升级），无需手写递归；
   以源码为准重写处无（J44 结论与实测一致）。
