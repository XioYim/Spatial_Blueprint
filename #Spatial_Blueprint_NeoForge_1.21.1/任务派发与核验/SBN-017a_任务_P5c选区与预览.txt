一、背景与目标
========================================================

P5 第三段的前半。1.20.1 的 client\BlueprintSelectionRenderer（2520 行）把两类东西揉在一个类里：
  · 普通渲染（约 1500 行）：选区框、对齐模式、放置加载动画、工程 / 项目 / 子项目预览、胶水框、领地区块框、实体标签、预览广播、距离自动取消 —— 走 SBN-016 已验证的 outliner；
  · GPU 幽灵方块预览（约 700 行）：把蓝图方块烤成顶点缓冲画半透明幽灵方块（异步构建、分帧上传、着色器绘制、流体贴图）—— 1.21 里 BufferBuilder / VertexBuffer 全变了，留给 SBN-017b。
本任务搬前者，后者用「接口不变、方法为空」的占位顶住，让整个类照常编译运行，只是暂时没有幽灵方块本体。

要搬的文件（1.20.1 client\ 与 command\）：
  BlueprintSelectionRenderer(2520，去掉 VBO 实现，见三.2)、ClientProjectPreview(139)、ClientSubProjectPreview(148)、ClientEngineeringPreview(64)、
  PlacementPreValidator(151)、ForceBlueprintGuard(146，界面弹窗打 P6 桩)、command\SBClientCommands(117，下载界面打 P6 桩)
新增（1.21.1 独有）：开发用客户端命令 SBDevCommands（三.5），让没有界面的阶段也能拿到蓝图物品并手测预览。

三、已定方案
========================================================

总原则：几何、颜色、距离阈值、判断顺序、日志文本一律不改，只换 API；每个文件 diff -w 残差逐条进报告。

1. 事件与注册（K29 / K30：类留在客户端入口链里）
   a. BlueprintSelectionRenderer 的三个 @SubscribeEvent（onRenderLevel / onClientTick / onLevelUnload）改为由 SpatialBlueprintClient 用 NeoForge.EVENT_BUS.addListener 显式注册
      （RenderLevelStageEvent、ClientTickEvent.Post、LevelEvent.Unload，J50）；类里去掉 @OnlyIn / @Mod.EventBusSubscriber。
   b. ClientProjectPreview 的 tick 监听同样由入口注册；ClientProjectPreview / ClientEngineeringPreview 各自带的 LoggingOut 清理照 SBN-015 口径并入 clearAllCaches（含 ClientSubProjectPreview.clear、渲染器里该清的静态状态，逐类对照 1.20.1 带 LoggingOut 监听的类）。
   c. SBClientCommands：RegisterClientCommandsEvent（J50）由入口注册；命令树与翻译键逐字原样。
   d. 公共包（主类、block、item、network 等）里 0 处新增对本包的引用，除了 S2C_PlacementProgressMessage 客户端体与 ClientProjectStatusCache（客户端类）里的调用（K29）。
2. BlueprintSelectionRenderer 的 VBO 占位（为 017b 留缝）
   保留（原样搬）：AlignMode 与对齐偏移函数、放置加载动画（含 OpenTopAABBOutline 内部类）、包围盒缓存、Void / 工程预览设置 API、非法块扫描缓存、渲染事件与客户端 tick、预览广播、
   胶水框 / 领地区块框 / 项目预览 / 空白选区 / 次元选区 / 工程预览 / 项目与子项目预览、实体与容器标签、getPreviewTarget、渲染列表（RenderEntry / needRebuild 一整段）—— 这些是 CPU 逻辑与 outliner / 线框 / 文字，本任务必须真能画。
   占位（017b 实现）：PreviewVboSlot（方法集不变：markDirty / startBuildIfDirty / uploadOneChunk / draw / isBuilding / hasPending / uploadedCount / totalChunks / dispose，全部无操作，dispose 返回 0）、
   OtherPreviewRender 的 VBO 相关成员、buildChunks / uploadBuffer / drawVBO / emitTexturedCube / ensureWhiteSprite / 流体贴图 UV 缓存 / SELF_BUILDER 与 OTHER_BUILDER 线程池 / UPLOAD_CHUNK_SIZE。
   每一处占位写 SB-TODO(P5): 017b VBO（说明原来做什么，1.20.1 行号范围）；不要删掉方法签名，也不要重排类结构，017b 直接原位替换。
   GPU 相关 import（VertexBuffer / BufferBuilder.RenderedBuffer 等）随占位一并不引入，以编译过为准。
3. 1.21 API 改写（云端已 javap，第四节 J50）
   a. Minecraft.getPartialTick() 已不存在 → mc.getTimer().getGameTimeDeltaPartialTick(false)（渲染事件内优先用 event.getPartialTick()）。
   b. 物品数据：stack.hasTag()/getTag().getString("blueprintId") → AbstractBlueprintItem.getBlueprintId（null 补 ""，C12）；其余物品字段一律走已有访问器（getRotation / getXOffset / isLocked 等）。
   c. BlockState.rotate(Rotation) 已弃用（K20）→ rotate(LevelAccessor, BlockPos, Rotation)（渲染列表里有 player.level() 与 rp 可用）；hasChunkAt(BlockPos) 同 K20。
   d. Font.drawInBatch(Component, float, float, int, boolean, Matrix4f, MultiBufferSource, Font.DisplayMode, int, int) 在 1.21.1 仍在（J50）；LevelRenderer.renderLineBox 各重载仍在；RenderType.lines() 仍在。
   e. 网络：BlueprintNetwork.CHANNEL.sendToServer → BlueprintNetwork.sendToServer（sendPreviewUpdate / sendPreviewClear 等）。
   f. 顶点提交（LevelRenderer.renderLineBox 之外自己写的）按 K32；本文件里 Outline 系已在 016 搬完，不重复。
   g. mc.screen instanceof PlacementScreen / EngineeringBlueprintScreen（关界面的分支）→ SB-TODO(P6) 桩（说明原语义：距离自动取消 / 工程预览停用时关掉界面）。
   h. ForceBlueprintGuard 里 ErrorToastScreen.showExclusive → SB-TODO(P6)；NotifySound.clientError() 走 SBN-015 的 ClientNotifySound；BlueprintNetwork.CHANNEL → sendToServer。
   i. SBClientCommands 的 /sbp download：OtherPlayerDownloadScreen 两个分支（单人直接下载 / 多人开选择界面）→ 各打 SB-TODO(P6)，命令本身照常注册，无预览时的提示文本原样。
4. 放置进度与预览缓存接线
   a. S2C_PlacementProgressMessage 客户端体：progress < 0 → BlueprintSelectionRenderer.stopPlacementAnimation()，否则 setPlacementServerProgress(progress)（1.20.1 handleClient 原样）。
   b. ClientProjectStatusCache 两处：onStatus → ClientProjectPreview.onStatus / ClientSubProjectPreview.onStatus，clear → ClientSubProjectPreview.clear()（1.20.1 原样）。
5. 开发用客户端命令 client/SBDevCommands（云端补：没有界面就拿不到蓝图，手测预览必需）
   a. 仅当环境变量 SB_DEBUG_OUTLINER 非空时，由 SpatialBlueprintClient 通过 RegisterClientCommandsEvent 注册；未设置时命令不存在，对正常构建零影响（与 016 的 OutlinerDebug 同一开关，类头注释写明）。
   b. /sbdev capture <名字> [safe|sanitize|force]：向服务端发一条 CaptureAreaMessage（与界面「创建」用的是同一条消息，构造参数 clearAfterCapture=false、durationSeconds=0、FluidCaptureFilter.ALL，
      模式默认 safe；名字用 StringArgumentType.greedyString 或 word 均可）。服务端要求：手持已设好两个选点的空白蓝图（BlankBlueprintItem.getPoint1/2）。
   c. /sbdev align <off|start|center|end>：把主手蓝图物品的 ALIGN_MODE 组件写成对应值（SpatialBlueprintItem.setAlignModeStr，只改客户端本地的物品副本，用于让预览渲染器生效；不发包）。
      AlignMode 的枚举值以 1.20.1 BlueprintSelectionRenderer.AlignMode 为准，命令的四个词与枚举一一对应，写成可自动补全。
   d. 你要在报告与测试清单里写清「从零到看见预览」的完整命令序列（含拿空白蓝图并设好选点的 /give 组件写法 —— 组件名与值格式照 SpatialBlueprintComponents 的实际注册 ID 与 Codec，自己实测能用再写）。
6. OutlinerDebug 去重：本任务后 outliner 由 BlueprintSelectionRenderer 的 tick / 渲染驱动；OutlinerDebug 去掉 Outliner.tickOutlines() 与 onRenderLevel（避免每帧画两遍），
   四个测试对象的每 tick 刷新保留（环境变量开启时仍可复现 H4）；SpatialBlueprintClient 里对应注册同步调整。
